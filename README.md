# 班级三角色协作平台(workstation-saas)

一个面向中小学的 **B 端 SaaS**(单校整体采购),基于"班主任工作台"的产品灵魂,扩展为 **三角色** 协作平台:

| 角色 | 定位 |
|---|---|
| **教师** | 班主任 / 副班主任 / 任课老师。继承原工作台的教室可视化、考勤、点评、随机点名、排座、成绩录入与分析、学生档案、AI 助手。 |
| **管理** | 校长 / 教导主任 / 年级组长 / 信息中心。看板、报表、组织架构、通知下发。 |
| **家长** | 主家长 / 次要家长。查看自己孩子的信息,接收通知,结构化回执。 |

此外,平台提供**监控画面接入**模块,把学校本地已有摄像头的实时画面桥接到 Web,按角色权限展示。

## 本地开发

### 环境要求

- Python 3.12 + [uv](https://docs.astral.sh/uv/)
- Node.js ≥ 20
- Docker(含 Compose v2),本地 Postgres / Redis 与后端测试都依赖它

首次拉取后安装依赖:

```bash
cd server && uv sync
cd apps/web && npm ci && npx playwright install chromium
```

### 启动顺序

在仓库根目录依次执行:

```bash
make dev        # 启动 Postgres 16(5432)和 Redis 7(6379)
make migrate    # 执行 Alembic 迁移
make seed       # 写入开发种子数据(重复执行会输出 already seeded)
make backend    # 后端 http://localhost:8080,接口都在 /api/v1 下
make web        # 前端 http://localhost:5173,/api 由 Vite 代理到 :8080
```

`make backend` 和 `make web` 各占一个终端。停止数据库用 `make dev-down`。

### 配置 AI

AI 服务由学校统一配置,API Key 加密后存在数据库里,不进任何文件。用命令行配置(Key 只从标准输入给):

```bash
cd server
printf '%s\n' "$YOUR_KEY" | uv run python -m app.cli ai-config set --provider deepseek --api-key-stdin
uv run python -m app.cli ai-config show    # 显示当前配置(Key 只露末 4 位)
uv run python -m app.cli ai-config test    # 测试连通性
uv run python -m app.cli ai-config clear   # 清除
```

`--provider` 可选 `deepseek`、`qwen`、`kimi`、`glm`、`doubao`、`silicon`、`custom`(任何 OpenAI 兼容地址,配 `--base-url` 和 `--model`)。`--mask-forced` 让学校强制隐去姓名:开启后,老师在页面上关掉"隐去姓名"也无效,而且已有对话的追问、批量条目和复制提示词也一律脱敏。

不想连真服务商时,本地开发和 E2E 用仓库里的假服务:`node apps/web/e2e/helpers/fakeLlm.mjs`(监听 18089),然后 `ai-config set --provider custom --base-url http://127.0.0.1:18089/v1 --model fake-model --api-key-stdin`(Key 随便给一个假值)。

**`WS_MASTER_KEY`**:加密 API Key 用的主密钥,32 字节的 base64(`openssl rand -base64 32`)。`WS_ENV` 不是 `dev` 时必须设置;它必须和数据库里的配置一起备份,主密钥丢了或换了,已存的 Key 就解不开,只能重新 `ai-config set`。开发环境用内置的固定值。

### 学年升级

推荐用管理端的向导(`/admin/upgrade`,需要 `year.upgrade` 权限:校长、教导主任);批量脚本或排错时也可以用命令行:

```bash
cd server
uv run python -m app.cli year-upgrade suggest --name 2027-2028 --start 2027-09-01 --end 2028-07-15 --out plan.json   # 按现有班级生成方案
uv run python -m app.cli year-upgrade preview plan.json     # 预览:每个班升到哪、留级、毕业、新建
uv run python -m app.cli year-upgrade apply plan.json --yes # 执行
uv run python -m app.cli year-upgrade rollback --yes        # 回滚最近一次(新学年已有数据时会拒绝,并列出数量)
```

升级会保留往年的考试、点评和成长记录(往年记录只读);原任课老师看不到旧班,新班主任能看到学生往年的成长记录但不能删。年级组长默认跟届走,向导的“人员”一步可以逐个年级指定(多位也行)。升级前后的往年班级在管理端 `/admin/history` 只读查看(名单、考试、成绩,没有写入口)。

命令行 `suggest` 生成的方案现在总是带 `grade_heads` 数组(每个新年级一项,沿用原年级组长)。**手改方案里的年级名时,要同步改 `grade_heads` 里对应的 `grade_name`,或把 `grade_heads` 显式设为 `null`**(退回按原年级跟届的旧规则);只改年级名、不动 `grade_heads`,`preview` / `apply` 会返回 400“新学年没有 X”。回滚检查除了原有的事件表之外,还会统计升级后在新学年里手动新建的年级、班级、任职和管理岗,有就拒绝并列出数量。

### 测试

```bash
make test                     # 后端 pytest(testcontainers 起真 Postgres / Redis)+ 前端 Vitest
cd server && uv run ruff check . && uv run ruff format --check .
cd apps/web && npm run lint && npx tsc -b
cd apps/web && npm run e2e    # Playwright:冒烟、教室、宽屏、成绩、学生、AI 助手、档案、桌椅排列、管理端、M3b(通知、联考、考勤报告、审计与 AI、学年升级)、M4a(建家长账号并在手机视口登录、两个孩子与排名开关、老师兼家长、毕业只读与回滚)、M4b(班级公告实时到达与回执、年级家长通知、截止与撤回、老师回执、解绑后实时下线)流程
```

`npm run e2e` 不会自己起服务,需要先按上面的启动顺序把数据库、后端和前端都跑起来;建议先 `make reset-db`。AI 配置存在数据库里,`reset-db` 会把它清掉:跑 E2E 前要先起假服务(`node apps/web/e2e/helpers/fakeLlm.mjs`),再用上面“配置 AI”一节的命令把 AI 配到假服务;`ai.spec.ts` 发现配置没指向 `fake-model` 会直接失败,不会把数据发给真服务商。用例会自己恢复改动过的数据(考勤点回出勤、点评撤销、座位存回种子布局;删掉 `E2E` 开头的考试、`测试` 开头的学生,清空王小一的个人笔记),可以重复跑。AI 与档案用例用 API 清掉自己建的对话、评语和成长记录。`m3b` 用例会留下已撤回的通知和已冻结的 `e2e_audit_` 开头账号(通知与账号都不能删),联考、分数、学年升级则当场还原,不影响其他用例。`m4a` 用例每次用一个随机的虚构手机号建家长账号,结束时解绑;账号随之归档,留在库里,不影响重复跑(`make reset-db` 可清掉);它还会临时改「家长可见排名」开关、建一场 `E2E` 开头的考试并在结束时还原 / 删除。`m4b` 用例发出的通知结束时都撤回(通知不能删,留在库里是“已撤回”),并用随机的虚构手机号建一个家长账号、结束时解绑(账号归档留库)。API 建考试会把预设科目写回 `classes.subjects`(种子里原本为空),不影响重复跑。

### 常见故障

- **testcontainers 报错连不上 Docker**:Docker 没有启动。先启动 Docker Desktop,再跑 `make test`。
- **`make dev` 报 5432 / 6379 端口被占用**:本机已有别的 Postgres / Redis。可以停掉它们;或者写一个不提交的 compose 覆盖文件改宿主机端口,例如:

  ```yaml
  # deploy/docker-compose.local.yml(不要提交)
  services:
    postgres:
      ports: !override ["15432:5432"]
    redis:
      ports: !override ["16379:6379"]
  ```

  用 `docker compose -f deploy/docker-compose.dev.yml -f deploy/docker-compose.local.yml up -d --wait` 启动,之后在命令前带上环境变量指向新端口:

  ```bash
  export WS_DATABASE_URL=postgresql+psycopg://workstation:workstation@localhost:15432/workstation
  export WS_REDIS_URL=redis://localhost:16379/0
  make migrate && make seed && make backend
  ```

  后端仍监听 8080,前端代理无需改动。
- **登录提示"失败次数过多,请 15 分钟后再试"**:同一账号连续 5 次密码错误会锁定 15 分钟。等锁定过期,或清空开发 Redis:`redis-cli FLUSHDB`(改过端口时加 `-p 16379`);本机没装 `redis-cli` 时用 `docker compose -f deploy/docker-compose.dev.yml exec redis redis-cli FLUSHDB`。

### M2c AI 与学年

| 功能 | 做什么 | 谁能用 |
|---|---|---|
| AI 助手(`/teacher/ai`) | 14 个模板(备课、作业、家长沟通、评语、家长会发言稿、成绩分析报告等)、自由对话、追问 / 停止 / 重新生成、复制提示词(给自己的 AI 工具用)、导出 Word | 有 `ai.use` 的老师;班主任模板需 `ai.class`,成绩分析报告需成绩读权限,不够的模板显示为禁用 |
| 批量评语 | 选多名学生逐条生成,可一键保存为评语 | 班主任 |
| 隐去姓名 | 姓名换成 `【学生07】` 这样的编号再发给服务商,回复里再换回真名;电话、证件号一律过滤;联系人不进提示词 | 默认开;学校强制时老师不能关 |
| 成长记录 | 档案抽屉里添加 / 删除成长记录,往年记录只读 | 班主任、副班主任可写;删别人写的记录需要班主任 |
| 评语 | 档案抽屉里的评语页签,可由 AI 生成后保存 | 班主任(副班主任和任课老师看不到评语页签内容) |
| 点评明细与撤销 | 档案成长记录页签里看前 40 条点评,撤销自己给的那条 | 给分人本人 |
| 分析页 AI 按钮 | AI 写分析报告、给退步同学家长写沟通消息 | 有对应模板权限的老师(成绩分析报告需成绩读权限,家长沟通需班主任) |

AI 的所有调用都经后端:脱敏、过滤、审计(每次生成一条 `ai.generate`,不记内容)都在服务端做;前端拿到的永远是真名文本。

### M2a 教室交互

教师端教室页(`/teacher/classroom`)底部的模式条切换四种模式,底部操作台跟随模式变化,待办与最近点评在操作台最右端的"待办与点评"抽屉里:

| 模式 / 功能 | 做什么 | 谁能用 |
|---|---|---|
| 日常 | 教室场景、悬停卡(学号 / 职务 / 今日考勤 / 本周积分)、点学生打开档案、空闲小动画 | 所有能看本班的老师 |
| 考勤 | 点学生轮转 请假 → 缺勤 → 迟到 → 出勤;确认考勤、全部出勤、按月导出 CSV;日期以学校时区为准 | 班主任、副班主任写;任课老师只读 |
| 点评 | 点学生选理由加减分(8 秒内可撤销)、全班 +1、积分榜、导出点评 | 班主任、副班主任、任课老师(任课老师记入任教科目) |
| 排座 | 点选或拖拽交换、随机打乱、男女同桌、固定座位、桌椅排列(排座条按钮,同「更多操作 · 班级设置」)、打印;两人同时改时后保存者收到冲突提示 | 仅班主任 |
| 班级设置 · 桌椅排列 | 每张桌子单人 / 双人 / 三人;行列按人数自动排或自己设定;讲台两边各 0–2 张单人桌;按学号横着 / 竖着排或保持现状;教室名称;预览实时计算,保存后座位按新桌椅排好;名单增删时自动增减排 | 仅班主任(有 `seating.write`);其他老师只看画面 |
| 随机点名 | 跳过今天请假 / 缺勤的同学,"回答得好 +1" | 日常模式的操作台上直接显示,考勤 / 点评模式在"更多操作"里 |
| 黑板 / 全屏 / 缩放 | 编辑左右黑板和倒计时;全屏投屏(日常 / 点评模式下不投出考勤标签);缩放、平移 | 黑板仅班主任 |

右上角头像菜单("账号菜单")里的"我的偏好"可以选老师形象、开关空闲小动画、维护点评理由;学生档案"概览"页可以设置职务(仅班主任)。

### M2b 成绩

顶栏的“成绩”“学生”两个入口,加上学生档案和教室页的成绩模式:

| 功能 | 做什么 | 谁能用 |
|---|---|---|
| 成绩页(`/teacher/scores`) | 建 / 改 / 删考试;表格录入(键盘、Excel 粘贴、按表头导入),自动保存;总分与排名;导出成绩 | 班主任全部科目、可导出;任课老师只录、只看本科目,可建只含本科目的考试并改 / 删自己建的(含其他科目的考试删不了),不能导出 |
| 分析页(`/teacher/analysis`) | 平均分 / 及格率 / 优秀率等 KPI、成绩分布与趋势图表、排名与关注名单 | 班主任全部科目;任课老师只有本科目的指标和排名;校长等管理角色后端已有只读 + 导出权限,页面在 M3 |
| 学生页(`/teacher/students`) | 名单表格、添加 / 编辑 / 删除(含座位、联系人、住校)、批量导入、导出名单 | 班主任;任课老师只看名单,不能增删改和导出 |
| 学生档案 | 抽屉里的概览(含累计积分、本月考勤、生日)、成绩页签(排名曲线、学科雷达)、班主任个人笔记 | 能看本班的老师都能开档案,字段按权限显示(任课老师看不到家庭信息,副班主任只看基本信息,看不到学习情况、性格等);成绩页签需有成绩读权限;个人笔记仅班主任本人 |
| 教室成绩模式 | 选考试,桌面按名次着色、进退步角标、无成绩变暗、色阶图例;投屏时不着色、不显示角标和图例 | 有成绩读权限的老师(任课老师按本科目排名) |
| 优带弱排座 | 按最近一场考试名次首尾配对、打乱桌序,尊重固定座位 | 仅班主任(排座权限) |
| 最近考试 | “待办与点评”抽屉里的最近考试、平均分与历次平均得分率曲线 | 有成绩读权限的老师 |

开发环境下 `/dev/classroom` 是教室画面的调试页:不连后端,用示例数据调排列数、模式、投屏、学生姿态和老师动作,方便看画面。

### M3a 管理端

登录后按身份分流:只有管理身份进 `/admin`,有教师身份进 `/teacher`,两种身份都有的在头像菜单里切换。

| 页面 | 做什么 | 谁能用 |
|---|---|---|
| 今日关注(`/admin/today`) | 在读、出勤率、请假 / 缺勤 / 迟到、考勤确认进度;缺勤与请假名单、还没确认考勤的班、本周点评(班级净分、需要关注的同学、老师点评次数);点学生开档案抽屉 | 校长、教导主任(全校),年级组长(本年级) |
| 全校看板(`/admin/board`) | 按年级页签看每个班的教室缩略图和出勤 / 缺勤 / 本周点评;整张卡片可点,进单班只读页(看教室、悬停看学生、开档案,没有任何写入口) | 同上 |
| 组织架构(`/admin/org`) | 学校信息、学年(含第二学期开学日期)、年级(学段)、班级增删改、班主任 / 副班主任 / 任课老师任职(换班主任时旧的立刻卸任)、管理岗;班级信息页 | 信息中心、校长、教导主任(`org.manage`);加减校长 / 信息中心岗位还需要账号管理权限 |
| 账号(`/admin/accounts`) | 新建(显示一次临时密码)、编辑、重置密码、冻结 / 解冻(冻结后对方下一次请求即下线)、CSV 批量导入(单次最多 500 行,全有效才建) | 信息中心、校长 |
| 学校设置(`/admin/settings`) | 学生标签池(可改名,学生身上同步)、功能开关(本周之星、本月寿星当场生效,「家长可见排名」「家长收到负向点评」在家长端下一次请求即生效,「AI 内容需审核后下发」决定之后 AI 生成的评语默认是否给家长看,其余开关先存,监控上线后生效) | 信息中心、校长 |

修改密码在头像菜单里;新账号和被重置密码的账号首次登录会被带到改密码页。

### M3b 联考、报表、通知与学年

| 页面 | 做什么 | 谁能用 |
|---|---|---|
| 年级联考(`/admin/grade-exams`) | 给一个年级建联考(各班自动生成同名班级考试,统一科目与满分),看各班录分进度,新班可补建;联考关联的班级考试老师不能改名、改科目、删除,录分照常 | 校长、教导主任、年级组长(本年级) |
| 成绩汇总(`/admin/reports/scores`) | 一场联考的班级对比(平均分 / 及格率 / 优秀率)、点班级看学生成绩与班级 / 年级名次,导出 CSV | 同上(只含自己看得到的班) |
| 考勤报告(`/admin/reports/attendance`) | 按月看各班的应到、出勤、请假、缺勤、迟到和出勤率(只统计班主任确认过考勤的日子,应到人次按每天在读人数算),点班级看学生明细,导出 CSV、打印 | 校长、教导主任、年级组长(本年级) |
| 审计日志(`/admin/audit`) | 按时间、操作人、分组筛选,看每条操作的中文名、对象、IP 与结果,被拒的访问可单独筛;只读,不能导出或删除 | 校长、信息中心 |
| AI 使用(`/admin/ai/usage`)、AI 配置(`/admin/ai/config`) | 使用:按月看调用次数与每人用量;配置:在页面上选服务商、地址、模型和 Key 并测试连接(换服务商或地址必须重填 Key) | 使用:校长、教导主任;配置:校长、信息中心 |
| 通知(`/admin/notices`) | 写通知发给全校老师 / 某年级 / 某班 / 指定的人,看已读数、撤回;老师和管理员的顶栏铃铛实时收到(WebSocket,断线自动重连并补拉),点开标为已读 | 发:校长、教导主任、年级组长(年级组长不能发全校);收:所有登录用户 |
| 学年升级(`/admin/upgrade`) | 向导:新学年 → 班级去向 → 学生例外 → 新建班级 → 人员(逐个年级指定年级组长)→ 预览 → 执行;可回滚(新学年已有手动改动时拒绝并列出) | 校长、教导主任 |
| 往年班级(`/admin/history`) | 选一个往年学年,只读看班级、名单、考试与成绩 | 校长、教导主任(年级组长能进页面但看不到往年班级,直接访问返回 403) |

管理端顶栏按组收纳:今日关注、全校看板、通知直接显示,其余收进「学校管理」「联考与报表」「系统」三个下拉(只剩一项的组直接显示成链接,没有权限的组不显示);768–1023 宽只显示图标,768 以下(含手机 375 宽)是可横向滚动的图标条。

后端的实时推送走 `GET /api/v1/ws`(令牌在建连后的第一条消息里给,不进 URL);开发时 Vite 对 `/api` 的代理已开启 WebSocket 转发。账号被冻结后,已打开页面的 WebSocket 会被立刻断开。

### M4a 家长账号与看孩子

| 页面 | 做什么 | 谁能用 |
|---|---|---|
| 档案「家长」页签(`/teacher/students` 打开学生档案) | 加家长(手机号 + 称呼 + 关系;已有账号的手机号直接绑到原账号,不改原密码)、设为主家长、重置密码、解绑;每个孩子 1 位主家长 + 最多 3 位次要家长;临时密码只在建号 / 重置那一次的对话框里显示 | 该学生当前班的班主任(同时是教职工的账号不能由班主任重置) |
| 评语「给家长看」开关 | 每条评语可选是否给家长看;学校开了「AI 内容需审核后下发」时,AI 生成的评语默认不给家长看(老师打开开关后家长才看得到) | 有评语权限的老师 |
| 家长端今日(`/parent/today`) | 今日出勤、今日点评与本周积分、迷你教室(别人的座位只有位置、没有姓名,孩子的座位带高亮)、班级信息 | 家长 |
| 家长端成长(`/parent/growth`) | 成长记录按学年、评语按学期、点评历史(无限下拉) | 家长 |
| 家长端成绩(`/parent/grades`) | 考试列表与各科成绩、班级平均与最高、名次或段位(看学校开关) | 家长 |
| 家长端档案(`/parent/profile`) | 只读档案;主家长可改家庭联系人(最多 2 组) | 家长;改联系人限主家长 |

家长端手机优先:底部页签、375 宽无横向滚动、可点区域不小于 44 px、避开 iOS 安全区,浅 / 深两套主题;一个家长有多个孩子时用顶栏下拉切换。孩子毕业或离校后,家长账号转为只读(只看成长与成绩),满 365 天归档;`cd server && uv run python -m app.cli parent-archive [--dry-run]` 执行归档,定时执行归 M5 部署包。学年回滚现在必须带 `upgrade_id`,只能回滚最近一次未回滚的升级。

### M4b 通知到家长与回执

| 页面 | 做什么 | 谁能用 |
|---|---|---|
| 班级公告(`/teacher/notices`) | 给本班在读学生的主家长发公告;可设回执(已知晓 / 单选 2–5 项,可允许留言)和截止时间;「我发出的」里看已读、回执数,打开回执统计、导出 CSV、撤回 | 本班班主任(有 `class.notice` 权限) |
| 管理端通知(`/admin/notices`) | 对象可选老师或家长;家长对象有全校 / 年级 / 班(没有“指定的人”);发给指定的人时有人已被冻结会提示并可一键去掉;同样有回执设置与统计 | 校长、教导主任、年级组长(年级组长没有“全校”) |
| 家长端通知(`/parent/notices`) | 所有孩子的通知放在一起,未读加粗、待回执有标记;展开后按要求点「已知晓」或选项并留言,截止前可修改;「通知」页签显示未读数,新通知到达时弹出提示 | 家长 |
| 铃铛 | 老师收到需要回执的通知时,在铃铛里直接回执 | 老师、管理者 |

通知发给家长时,收件人是范围内在读学生的在用绑定的主家长(次要家长、只读绑定不收);一个家长有两个孩子都在范围内时只收到一条,通知上写明涉及的孩子。已截止、已撤回、孩子已毕业的通知不能回执。回执统计按学生一行,家长对象会列出还没有绑定家长的学生数。解绑导致账号归档时,该家长已打开的页面会立刻被登出。

## 部署

面向学校信息中心:离线包安装、HTTPS 三种方式、备份与恢复、升级、诊断包和常见故障,全部写在 [`deploy/README.md`](deploy/README.md)(随离线包一起发)。支持 **Ubuntu 22.04 / 24.04 LTS、x86_64**,v1 不支持 Windows Server。构建离线包:`deploy/release/build-bundle.sh <版本>`(产物在 `dist/`,不提交)。
