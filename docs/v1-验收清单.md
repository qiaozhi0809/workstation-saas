# v1 真机验收清单

> 给学校信息中心 / 运维同学用。分两轮:**A. Phase 1.5** 在真实 Ubuntu 服务器上安装 0.7.2 并试用;**B. Phase 3** 用 1.0.0-rc.1 的离线包从 0.7.2 升级上去再验一遍。每项一行,验过就在 `[ ]` 里打勾,预期不符的把看到的原文记在行尾(照抄屏幕上的文字即可)。
> 命令都在部署目录(如 `/opt/workstation`)里执行;装机用的是 root(`sudo`)就全程加 `sudo`,见 [部署手册](../deploy/README.md) 第 3 节「用哪个用户执行脚本」。文中「第 N 节」都指 `deploy/README.md`。
> 末尾 C 节是持续集成(CI)的运行证据,由开发方填写,学校不用管。

## A. Phase 1.5:在真机上安装 0.7.2

### A.1 安装与备份(第 1、2、3、7 节)

- [ ] **系统检测**:在 Ubuntu 22.04 或 24.04(x86_64)上执行 `sudo ./scripts/install.sh`。预期:直接进入问答(学校名称、管理员登录名、密码、访问地址、证书方式),没有"不支持的系统"之类的拒绝。
- [ ] **装完能用**:脚本最后打印访问地址;在校园网内的电脑用浏览器打开,内部证书方式先按第 4 节「方式 1」装根证书;管理员首次登录被要求改密码,改完进入管理端。记录:安装耗时 ___ 分钟。
- [ ] **服务器时区**:执行 `timedatectl`,把 `Time zone` 一行抄下来:___(很多服务器是 UTC,后面两项要用)。
- [ ] **定时备份已启用(0.7.2 基线)**:`sudo systemctl list-timers workstation-backup.timer`,抄下 `NEXT` 一列:___。0.7.2 的定时器按**服务器系统时间**的 02:30 执行——系统时区是 UTC 时,NEXT 会显示 02:30 UTC(北京时间上午 10:30),这是 0.7.2 的已知问题,升级到 rc.1 后在 B.2 复查应变成学校时区的 02:30。
- [ ] **手动备份**:`sudo systemctl start workstation-backup.service`,然后 `ls -l backups/`。预期:多出一个 `ws-backup-<日期时间>-v0.7.2.tar.gz`;`sudo journalctl -u workstation-backup.service -n 20` 没有报错;管理端「学校设置 → 系统」卡的"上次备份"显示刚才的时间。
- [ ] **用错用户的提示(0.7.2 基线)**:换一个普通用户(不加 sudo)执行 `./scripts/backup.sh`。0.7.2 会报类似"另一个备份、恢复或升级正在进行"的误导文案,属已知问题;抄下原文:___。升级后在 B.2 复查应变成"该部署由 root 安装,请用 sudo 执行"。
- [ ] **磁盘余量**:`df -h /opt/workstation`(换成你的部署目录)与 `df -h /var/lib/docker`。预期:两个盘都 ≥ 20 GB 可用(安装与升级的门槛)。记录:___ GB / ___ GB。
- [ ] **登录日志里的 IP 是真实地址**:从校园网内另一台电脑登录一次,管理端「系统 → 登录日志」里这一行的 IP 应是那台电脑的内网地址(如 `192.168.x.x`),**不是** `172.30.0.x`。若是 `172.30.0.x`,说明 `.env` 的 `WS_TRUSTED_PROXIES` 配错,按第 5 节与第 12 节「内网拓扑」改。

### A.2 安全(第 5、11、12 节)

- [ ] **校外看不了摄像头**:只有系统在校外也能打开时才做(手机关 Wi-Fi 用流量访问;系统只在校园网内可达则记"不适用")。校外登录后进教室页「看看教室」:播放器显示"只能在校园网内观看",画面不出来。
- [ ] **`WS_TRUSTED_PROXIES` 配对**:`sudo grep WS_TRUSTED_PROXIES .env`。预期:值里含 `172.30.0.0/24`(0.7.2 的 compose 子网),没有 `0.0.0.0/0`、`10.0.0.0/8` 这类宽网段;A.1 最后一项的 IP 正确就说明配对了。
- [ ] **登录限速**:用一个测试账号连续输错 5 次密码。预期:第 6 次提示账号已锁定、15 分钟后再试;「登录日志」里能看到"密码错误"与"已锁定"的行。
- [ ] **两步验证开启**:管理端「学校设置 → 账号安全」打开"允许账号开启两步验证"并保存;用一个老师账号在头像菜单「账号安全」扫码开启(要再输一次当前密码);退出再登录,密码正确后出现验证码页,输 6 位码进入。
- [ ] **两步验证重置**:信息中心在「账号」页对该老师点「重置两步验证」。预期:该老师下次登录只要密码,之后可以自行重新开启;老师当时开着的页面不受影响(属设计);「审计日志」里有一条"重置两步验证"。

### A.3 摄像头(第 12 节)

- [ ] **先开总开关再登记**:「学校设置 → 监控」打开总开关并保存,之后「摄像头」页才能新建(开关关着时页面顶部有提示、不能新建,属设计)。
- [ ] **记录设备**:摄像头品牌型号 ___;登记的是主码流 / 子码流 ___;「测试连接」返回的编码 ___(`h264` / `hevc`)。
- [ ] **测试连接(H.264 子码流)**:新建摄像头后点「测试连接」。预期:成功、有预览图、编码 `h264`。
- [ ] **测试连接(H.265 主码流)**:再登一路 H.265 主码流。预期:测试成功,但提示浏览器不能直接播放、建议改用 H.264 子码流或勾选"转码";播放时显示"这路摄像头的视频编码浏览器不支持"。
- [ ] **直播**:班主任在教室页「看看教室」。预期:几秒内出画面。记录:点开到出画 ___ 秒;对着一块走秒的钟拍,画面比实际慢 ___ 秒。
- [ ] **停更后恢复(0.7.2 基线)**:正在播时拔掉摄像头网线 30 秒再插回。0.7.2 预期:画面定格,老师**刷新页面**后恢复(后台几十秒内自动重启这一路)。升级后在 B.4 复查 rc.1 的自动重连与「重试」。
- [ ] **九宫格与资源**:校长看板「监控」侧栏切到九宫格,让 9 路同时播;服务器上 `docker stats --no-stream` 看 `stream-worker` 容器。记录:不转码 ___ 路 CPU ___% / 内存 ___ MB;勾了"转码"的 ___ 路 CPU ___% / 内存 ___ MB。
- [ ] **同时观看上限**(课后做,改 `.env` 会重建服务、中断约半分钟):把 `.env` 里 `WS_STREAM_MAX` 临时改成 2、`docker compose up -d`,再开第 3 路。预期:第 3 路显示"同时观看的摄像头太多,请稍后再试",前两路不受影响;验完改回并再 `up -d`。

### A.4 各端走查(真机浏览器;手机用 375 宽左右的机型)

- [ ] **教师端全屏首次 Esc**:教室页点「全屏」,打开一个浮层(如头像菜单),按一次 Esc。记录 Chrome / Edge 各一次:退出全屏时浮层是否同时关闭 ___ / ___。
- [ ] **投屏**:教室页接投影 / 扩展屏(或镜像),切换五种模式、随机点名、编辑黑板。预期:舞台、点名卡、黑板显示完整,退出投屏后页面正常。
- [ ] **家长端 375 宽**:家长账号在手机上打开「成绩」某场考试的详情。预期:每科两行一张卡,页面不能左右滑动;多个孩子的家长顶栏校名让位、孩子切换下拉能点开且名字看得清(只有一个孩子时校名显示)。
- [ ] **教师端触屏**:在手机 / 平板上打开教师端。预期:顶栏导航、学生档案抽屉的页签、学生名单表格里的按钮、对话框右上角关闭按钮都明显比电脑上大、好点;电脑上尺寸不变。

## B. Phase 3:用 rc.1 离线包从 0.7.2 升级上来

### B.1 升级(第 9 节「从 0.7.2 升级到 1.0.0」)

- [ ] **升级前备份并离机保存**:`sudo ./scripts/backup.sh`,把最新的 `backups/ws-backup-…-v0.7.2.tar.gz` 复制到另一台设备。
- [ ] **先覆盖新包的脚本**(这一步 0.7.2 → rc.1 特有,漏了会被 0.7.2 的脚本以"大版本升级需要专门的迁移说明"拒绝、系统不受影响):在部署目录里执行第 9 节「从 0.7.2 升级到 1.0.0」的第一条 `tar` 命令(把 `<新包>` 与版本号换成实际路径与 `workstation-deploy-<新版本>.tar.gz` 里的版本)。预期:`ls scripts/` 多出 `rollback.sh`。
- [ ] **执行升级**:`sudo ./scripts/upgrade.sh <新包路径>/workstation-deploy-<新版本>.tar.gz`,课后做(服务会重启几分钟)。预期:屏幕依次出现"备份完成"、迁移预检通过、保存快照、覆盖文件、服务健康;root + systemd 的还有"已……重写 systemd 定时备份单元";末尾打印清理旧镜像的 `docker image rm …` 命令(不用立刻执行)。记录升级耗时 ___ 分钟。
- [ ] **数据库已迁到 0013**:`sudo docker compose exec -T postgres psql -U workstation -d workstation -tA -c "select version_num from alembic_version"`。预期输出 `0013`。
- [ ] **快照目录与状态文件**:`ls backups/`。预期:多出 `pre-upgrade-0.7.2-<时间>/`;`ls backups/.ws-upgrade-state` 提示不存在(升级成功已清除)。
- [ ] **`.env` 补键**:`sudo grep -E 'WS_SUBNET|WS_TRUSTED_PROXIES' .env`。预期:多出 `WS_SUBNET=172.30.0.0/24`,`WS_TRUSTED_PROXIES` 包含它。
- [ ] **升级后数据都在**:登录管理端与老师端,随便看一个班的名单、一场考试、一条通知的回执统计。预期与升级前一致。说明:升级前已升过学年的学生,其**旧**通知的回执统计里班名显示的是升级那一刻孩子所在的班(属预期,与升级日志 0013 的回填规则一致)。
- [ ] **回退演练(课后、可接受十几分钟停机时做)**:`sudo ./scripts/rollback.sh backups/pre-upgrade-0.7.2-<时间> --yes`。预期:先列出将要做的事,然后因为"数据库已被新版本迁移"退出码 3、应用容器停下、数据库容器仍在,屏幕给出两条路——A 保留数据重跑 `upgrade.sh`,B 用升级前备份 `restore.sh` 回旧版(会丢升级后的数据)。**按 A 走**:`sudo ./scripts/upgrade.sh <同一个新包>`。预期:再次成功,登录正常、刚才看的数据还在。
- [ ] **中断后的提示(了解即可,正常升级不会遇到)**:如果升级在"覆盖程序文件"之后被断电或强制结束,之后运行 `upgrade.sh` / `rollback.sh` / `install.sh` 都会先说"上次升级(0.7.2 → …)没有确认成功",并给三选一(回到旧版 / 同一个包重跑 / 已确认新版正常则删除 `backups/.ws-upgrade-state`),见第 9 节「升级中断后怎么办」。真遇到时把屏幕原文抄下来:___。

### B.2 安装项复查(rc.1 脚本;第 3、7、9 节)

- [ ] **定时器带学校时区**:`sudo systemctl list-timers workstation-backup.timer`。预期:`NEXT` 是学校时区(默认 Asia/Shanghai)的凌晨 02:30,即使 A.1 记录的系统时区是 UTC;`sudo systemctl cat workstation-backup.timer` 里有 `OnCalendar=*-*-* 02:30:00 Asia/Shanghai`。抄下 NEXT:___。
- [ ] **手动备份(rc.1)**:`sudo systemctl start workstation-backup.service`。预期:`backups/` 多出 `…-v<新版本>.tar.gz`;`tar -tzf backups/<新文件>` 列出 `db.dump`、`env`、`caddy.tar`、`config.tar`、`manifest.json`;管理端系统卡"上次备份"更新。
- [ ] **开机补跑**:挑一个晚上让服务器在 02:30 之前关机、次日开机。预期:开机后几分钟内自动补做一次备份(`journalctl -u workstation-backup.service` 能看到等待数据库就绪与备份完成),不报错。
- [ ] **用错用户的新提示**:普通用户(不加 sudo)执行 `./scripts/backup.sh`。预期:报"该部署由 root 安装(.env 的属主是 root),请用 sudo 执行同一条命令",不再是"另一个备份正在进行"。
- [ ] **磁盘门槛看两个盘**:`sudo docker info | grep -i 'docker root dir'`,对这个目录和部署目录各 `df -h`。预期:两处 ≥ 20 GB;不够时 `upgrade.sh` / `install.sh` 会提示"Docker 数据目录 … 所在磁盘可用空间不足"而不是悄悄失败。
- [ ] **系统卡的备份告警**:「学校设置 → 系统」卡。全新安装当天、首次定时备份前显示"从未备份,请检查定时任务"属正常;**次日**仍显示,或显示"上次备份是 N 天前,请检查定时任务"才需要按第 7 节检查定时器。
- [ ] **用 crontab 的学校**(非 root 安装才有):`crontab -l` 里按第 7 节加上 `CRON_TZ=Asia/Shanghai` 一行;次日 `journalctl -t workstation-backup` 能看到 02:30 的备份记录。
- [ ] **离线装 Docker 的清单**(只有服务器不能上网时才有):把实际用到的 `.deb` 文件名列表与 `docker compose version --short` 的输出记在这里,交给开发方回填手册:___。

### B.3 安全复查(第 5、11、12 节)

- [ ] **A.2 的五项在 rc.1 上再过一遍**:校外看摄像头(若适用)、`WS_TRUSTED_PROXIES`(现在应等于或包含 `WS_SUBNET`)、登录限速、两步验证开启、两步验证重置。
- [ ] **登录日志 IP 仍是真实地址**:同 A.1 最后一项。
- [ ] **管理员重置密码后旧页面下线**:老师开着教师端页面,管理员在「账号」页给他「重置密码」。预期:老师的页面立刻(或下一次操作时)回到登录页,用临时密码登录后被要求改密码。
