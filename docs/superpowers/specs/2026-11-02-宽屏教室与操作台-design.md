# 宽屏教室与操作台(M2a.6)设计稿

> 本稿是 M2a.5 之后、M2b 之前的一轮**只改 UI** 的改进。决定按来源分三类标注:**用户定**(2026-11-02 头脑风暴里用户逐项选定)、**用户确认**(协调者先提出、用户 2026-11-02 确认)、**撰写者默认**(本稿撰写时为不影响"做什么"的小问题定的默认值,用户可随时推翻)。

## 1. 意图与原因

用户在本地预览 `v0.2.5-m2a5-ui` 后提出三件事(原话):

1. **"16:9 投屏时教室页左右很空"**。原因:6 排 × 4 列的教室画面是 960 × 1292 的竖长幅,1920 × 1080 投屏下舞台约 1570 × 830,画面适应后只有约 600 px 宽,两侧各空出约 480 px。
2. **"画布能随意上下左右拖动,误触后画面会跑出视野"**。原因:`useViewport` 在"适应"状态下也允许拖动和滚轮平移;`clampView` 只保证教室留 140 px 在舞台内,一体机上手掌一蹭,教室就只剩一角。
3. **"菜单布局(底部模式条、右上工具群、排座工具条、顶栏)需要优化"**。现状是四处分散:舞台上方工具栏(随机点名 / 编辑黑板 / 模式附加按钮 / 缩放 / 全屏 / 概况栏)、工具栏下方模式操作条、舞台下方模式条、顶栏平铺四个操作;排座模式一行十个控件。

## 2. 目标 / 非目标 / 反目标

**目标**

- 16:9 屏幕上教室画面铺满舞台;两侧是装饰,核心内容(黑板、讲台、座位)和今天一样大。
- 平板 / 窄窗口自动裁掉两侧装饰,核心内容不缩小、不被裁。
- "适应"时画面锁定;放大后才能拖,且拖不出边界;"适应"一键回位。
- 模式切换、当前模式操作、全屏、概况栏合成一条底部操作台;缩放变成舞台右下角的小悬浮钮。
- 排座操作台只露常用按钮,次要操作收进"⋯";顶栏只剩班级信息、主题、头像菜单。

**非目标**

- 不改 `server/`、HTTP 契约、查询键、store、业务逻辑;不改任何模式的功能。
- 不做教室 SVG 的深色版(画面仍是浅色纸面)。
- 不给两翼装饰加交互或新动画。
- 不专门优化 375 手机宽度下的教室体验(只保证不横向滚动,同 M2a.5)。
- 不改家长端 `mini`、管理端 `overview` 的产品形态(它们 M3 / M4 才有页面)。

**反目标**(明确不要发生的)

- 不要为了"画满"在任何屏幕上把核心内容缩小或裁掉一部分座位。
- 不要让两翼出现需要老师看的信息(两翼随时可能被裁)。
- 不要让底部操作台在任何宽度出现横向滚动条,或把按钮挤出屏幕。
- 不要引入新的运行时依赖(见 §9)。

## 4. 约束

沿用 M2a.5 计划的全部 Global Constraints,本轮逐条适用:

- 版本锁定:React `18.3.x`、Vite `5.4.x`、Tailwind `3.4.x`、TypeScript `~5.6`、`shadcn@2.3.0`、`tailwind-merge@^2.6.0`;**本轮不新增任何运行时依赖**。
- **只改 UI**:不改 `server/`、HTTP 契约、查询键、store、业务逻辑;可见文案和可访问名称只允许 §10 文案变更表列出的改动。
- 颜色只用语义令牌类;`noLegacyStyles` 全仓库守卫保持通过。SVG 画面颜色只取 `art/palette.ts` / `art/kit.ts` 的常量(与今天的画法相同),不在 className 里写颜色。
- 弹层(对话框 / 抽屉)只用 `Modal` / `SidePanel`;舞台内浮层(点名卡、点评弹层、悬停卡,以及本轮新增的缩放悬浮钮)保持舞台内绝对定位、不走 portal。本轮新增的 `Popover` / `Menu` 是**锚定在触发按钮旁的非模态小浮层**,同样不走 portal(§9)。
- 原生 `<select>`、`checkbox`、`radio`、`type="date"`、`type="number"` 保留为原生控件。
- 新增动画和过渡在 `prefers-reduced-motion: reduce` 下关闭。
- 现有 Vitest + Playwright 全绿。测试改动分两类,都逐条写进 PR"偏差":
  - **只改定位方式**(允许,不放宽断言含义):控件挪了位置或要先点开浮层才出现——缩放组移到舞台、模式条并入操作台、排座 `放弃修改` / `固定座位` / `打印` 进 `⋯` 菜单(角色变 `menuitem`,禁用断言从 `toBeDisabled` 改为 `aria-disabled`)、`排数` / `列数` 要先点开行列弹层、顶栏 `我的偏好` / `退出登录` 要先点开头像菜单。
  - **有意改变预期**(只限两处):视口锁定(§6,适应时不再平移、缩放下限改为适应比例)与窄屏菜单删除(§8)。
- 教室 SVG:核心(安全区)内的现有画面只允许"整体平移"和 W3 的陈设区重排;座位层、桌椅、人物、特效、`classroom.css` 动画不改。

## 5. 宽场景技术方案

### 5.1 坐标系

今天 `computeLayout(rows, cols, opts)` 算出一间教室:宽 `coreW = 2·WALL + 2·SIDE + grid.w`,高 `H = 2·WALL + FRONT + PODIUM + TOP_PAD + rows·ROW + BACK`。6 × 4 时是 960 × 1292。

`computeLayout` 新增可选项 `aspect?: number`。不传时**与今天完全相同**(`mini`、现有测试都走这条)。传 `aspect` 时:

```
targetW = H × aspect
W       = coreW + 2 × ceil(max(0, targetW − coreW) / 2)     // 两翼对称、整数
dx      = (W − coreW) / 2                                     // 安全区左边
```

返回的 `Layout` 新增两个字段,原有字段含义不变、数值整体右移 `dx`:

| 字段 | 值 |
|---|---|
| `width` | `W`(场景宽) |
| `safe: Rect` | `{ x: dx, y: 0, w: coreW, h: H }`;不加宽时 `{ 0, 0, width, height }` |
| `wings: { left: Wing; right: Wing } \| null` | `dx = 0` 时为 `null`;`Wing = { wall: Rect; floor: Rect }` |
| `grid.x`、`zones[].rect.x`、`frontWall.x` | 今天的值 + `dx` |
| `podium.x` | `(W − PODIUM_W) / 2`(公式不变,因对称仍居中) |
| `seat()` / `head()` / `label()` | 由 `grid` 推出,自动带 `dx` |

两翼区域(场景坐标):

| 区域 | 矩形 |
|---|---|
| `left.wall` | `{ x: WALL, y: WALL, w: dx, h: FRONT }`(与核心前墙 `frontWall` 左端无缝相接) |
| `left.floor` | `{ x: WALL, y: WALL + FRONT, w: dx, h: H − 2·WALL − FRONT }` |
| `right.wall` | `{ x: dx + coreW − WALL, y: WALL, w: dx, h: FRONT }` |
| `right.floor` | `{ x: dx + coreW − WALL, y: WALL + FRONT, w: dx, h: H − 2·WALL − FRONT }` |

参考数值(`aspect = 16/9`):

| 排 × 列 | 核心 `coreW × H` | 场景 `W` | 两翼 `dx` | 陈设区 |
|---|---|---|---|---|
| 6 × 4(种子数据) | 960 × 1292 | 2298 | 669 | 宽屏重排(W3) |
| 6 × 6 | 1200 × 1292 | 2298 | 549 | 宽屏重排 |
| 8 × 8 | 1440 × 1548 | 2752 | 656 | 宽屏重排 |
| 4 × 8 | 1440 × 1036 | 1842 | 201 | 今天的陈设区(两翼 < 280) |
| 2 × 12 | 1920 × 780 | 1920 | 0 | 不加宽,`wings = null` |

### 5.2 画什么、画在哪(构图默认,草稿过目后定稿)

> 草稿过目:用户 2026-11-02 看过两翼草稿(1920 / 1024 等舞台截图)后答复"可以定稿",无修改意见;构图按本节默认实现。

`Scene` 的绘制顺序:房间 → **两翼** → 陈设区 → 前墙 → 桌椅 → 座位 → 讲台 → 聚光灯 → 积分气泡。

- `Room`(地板、后墙储物柜、右墙侧窗、左墙前后门)**代码不改**:它本来就按 `layout.width` / `height` 画,加宽后地板自然铺满,门和侧窗随墙移到场景两端,储物柜仍在课桌正下方。
- `FrontWall` **代码不改**:它只在 `frontWall` 矩形(核心宽)里排黑板 / 智慧屏 / 小展板 / 挂钟,随 `dx` 平移,所以安全区里的前墙与今天一模一样。
- 新增 `Wings`(两翼):先在两个 `wall` 矩形里补齐前墙底色和踢脚线(与 `FrontWall` 的墙色、底部 26 px 踢脚线同色同高,视觉上是一面连续的墙),再画装饰:

| 位置 | 内容(C1 / W3 / W4) | 放得下的条件 |
|---|---|---|
| `left.wall` | 一排窗户:窗框 + 天色 + 树冠剪影;窗数 = `floor((w − 24) / 144)` | 每扇窗 120 宽 + 24 间距;一扇都放不下就不画 |
| `left.floor` | 窗户投到地板上的斜向光斑(同 `Room` 侧窗光斑的画法) | 随窗数 |
| `right.wall` | 扩大的荣誉墙 / 公告栏:`班级公告`板(手写风短线)+ 一排奖状 + 贴纸 | `w ≥ WING_MIN` |

### 5.3 窄屏裁切规则

裁切不靠 `preserveAspectRatio`(SVG 仍按自然尺寸画在变换画布里,今天就是这样),而是靠**适应比例只看安全区宽度** + 舞台 `overflow: clip`:

```
fit.s = clamp(min(stage.w / safe.w, stage.h / H), FIT_MIN_S, FIT_MAX_S)
fit.x = (stage.w − W × fit.s) / 2          // 场景居中 = 安全区居中(两翼对称)
fit.y = (stage.h − H × fit.s) / 2
```

- 不加宽时 `safe.w = W`,公式退化为今天的 `fitView`。
- 加宽时 `safe.w = coreW` = 今天的 `content.w`,所以**任何舞台尺寸下适应比例都和今天相同**,核心内容大小不变。
- 舞台比场景宽(超宽屏):两侧露出舞台底色,与今天相同。
- 舞台比场景窄:两翼被对称裁掉;舞台比安全区还窄时变为按宽度适应,上下留空(与今天相同)。

### 5.4 什么保持不变

- 座位、桌椅、人物、积分气泡、聚光灯、教鞭指向:都由 `layout.seat/head/label` 推出,`dx` 自动带上,画法和动画参数不变。
- 悬停卡(`HoverCard` / `placeCard`)、点评弹层(`ReviewPopover`)、点名卡(`PickCard`)、拖拽影子(`useSeatDrag`):都按 DOM `getBoundingClientRect` 换算成**舞台坐标**,与 SVG 内部坐标无关,场景加宽 / 平移 / 裁切后自动跟着座位走,**不需要改**。
- 键盘聚焦到视口外的座位时平移(`ensureVisible`):逻辑保留,但"适应"状态下不触发(安全区本就完整可见,§6)。
- `mini`(家长)不传 `aspect`,画面不变;`overview`(管理端,M3)与教师端一样加宽。

## 6. 视口规则

以 `ClassroomMap/viewport.ts` 与 `useViewport.ts` 的现有代码为基础,改成两种状态:

| 状态 | 进入 | 允许 | 不允许 |
|---|---|---|---|
| **适应(锁定)** | 挂载、舞台尺寸变化(此前就是适应)、点"适应"、缩小到适应比例、舞台变大使当前比例 ≤ 新的适应比例 | Ctrl/⌘ + 滚轮放大、"放大"按钮、点座位 / 拖座位(排座) | 拖动平移、普通滚轮平移、"缩小"、键盘聚焦触发的平移 |
| **放大(可拖)** | 从适应状态放大 | 拖动 / 滚轮平移、继续缩放 | 把场景拖出边界 |

**边界夹取**(取代今天"至少留 140 px"的 `clampView`),逐轴:

```
len = 内容长度 × s
len ≤ 舞台长:  p = (舞台长 − len) / 2              // 这一轴放不满就居中、不可拖
len > 舞台长:  p ∈ [舞台长 − len, 0]               // 场景始终盖满舞台,拖不出边
```

内容长度用整个场景(含两翼):平板上放大后可以拖去看被裁掉的两翼。

**缩放**:下限 = 当前舞台的适应比例(取代 `MIN_S = 0.3`);上限 `MAX_S = 2.5` 不变;按钮步长 1.2 不变;缩放后若比例 ≤ 适应比例 + 1e-6 → 直接回到适应状态。舞台尺寸变化:适应状态重新适应;放大状态若当前比例 ≤ 新适应比例 → 回到适应,否则只做边界夹取。

**输入映射**(其余输入不变):

| 输入 | 适应状态 | 放大状态 |
|---|---|---|
| 按住空白处拖 | 无反应,不显示抓手光标 | 平移(夹取) |
| 普通滚轮 / 双指滑动 | 无反应(仍阻止页面滚动) | 平移(夹取) |
| Ctrl/⌘ + 滚轮 / 触控板捏合 | 以指针为中心缩放 | 同左 |
| 悬浮钮 缩小 / 适应 / 放大 | 缩小 `aria-disabled`;适应无变化;放大 | 缩小(到底回适应);适应回位;放大(到上限 `aria-disabled`) |
| 键盘聚焦到座位 | 不平移 | 必要时平移进视野(夹取) |

**缩放悬浮钮**由 `ClassroomMap` 自己渲染(新 prop `zoomControls?: boolean`,默认 `false`,教师教室页传 `true`):舞台右下角 `absolute bottom-3 right-3`,`role="group" aria-label="缩放"`,三个图标按钮名称与 `title` 仍是 `缩小` / `适应` / `放大`;悬浮钮上的按下事件不冒泡到舞台(不会触发平移 / 拖座位)。`viewportRef` 句柄(`zoomIn / zoomOut / fit`)保留,开发用的 `/dev/classroom` 和测试仍在用。

## 9. 新下拉组件:自写 `Popover` + `Menu`

M2a.5 计划明确"不引入 Radix DropdownMenu"。本轮需要三个锚定小浮层:头像菜单(顶栏)、`⋯` 更多(操作台)、行列弹层(操作台,里面是输入框,不是菜单)。

| 选项 | 优点 | 缺点 |
|---|---|---|
| **A 自写(推荐,W15)**:`overlay/Popover.tsx`(非模态 `role="dialog"`)+ `overlay/Menu.tsx`(`role="menu"`,基于 Popover) | 不加依赖;非 portal,舞台 / 操作台进全屏时天然可见;`fireEvent.click` 能直接测(项目没有 `user-event`);行列弹层本来就不是菜单,Radix DropdownMenu 也覆盖不了 | 键盘与焦点行为要自己写、自己测(约 150 行) |
| B 新增 `@radix-ui/react-dropdown-menu` | 键盘、typeahead、碰撞翻转现成 | 新依赖(AGENTS.md §6 要用户同意);默认 portal 到 `body`,全屏时要逐处传 `container`;它在 `pointerdown` 而不是 `click` 上打开,jsdom 里 `fireEvent.click` 打不开,现有测试风格要改;行列弹层仍需另做 |

行为约定(实现与测试以此为准):

| 行为 | Popover | Menu |
|---|---|---|
| 触发按钮 | `aria-haspopup="dialog"`、`aria-expanded`、`aria-controls` | `aria-haspopup="menu"`、`aria-expanded`、`aria-controls` |
| 打开 | 点击 / Enter / Space;焦点移到弹层内第一个可聚焦元素 | 点击 / Enter / Space / ↓;焦点移到第一个菜单项 |
| 键盘 | Tab 在弹层内正常移动;焦点移出弹层(`focusout` 且 `relatedTarget` 在弹层外)→ 关闭 | ↑↓ 循环、Home / End;Tab → 关闭并让焦点自然移走 |
| Esc | 关闭并把焦点还给触发按钮(走 `useEscapeLayer`,含输入法保护、只关最上层) | 同左 |
| 点外面 | `document` 上 `click`(捕获阶段)落在组件外 → 关闭,焦点不强制移动 | 同左 |
| 再点触发按钮 | 关闭 | 关闭 |
| 选中菜单项 | — | 执行 `onSelect` → 关闭 → 焦点回触发按钮;`aria-disabled` 项可聚焦、不执行 |
| 位置 | 包在 `relative inline-flex` 里,`side="top"` → `bottom-full mb-2`,`side="bottom"` → `top-full mt-2`;`align="start|end"`;`max-w-[calc(100vw-2rem)]` | 同左 |
| 样式 | `rounded-md border bg-popover p-1 text-popover-foreground shadow-md`,`z-40`;`motion-safe:` 淡入 | 同左;菜单项 `rounded-sm px-2 py-1.5 text-sm`,聚焦 / 悬停 `bg-accent` |

"点外面"用 `click` 而不是 `pointerdown`:到 `click` 时浏览器已经把焦点从输入框移走,`SizeInput` 的失焦提交先完成,弹层才卸载(W16)。
