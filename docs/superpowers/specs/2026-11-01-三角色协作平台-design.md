# 班级三角色协作平台 · 设计文档

## 0. 前言

### 0.1 项目定位

本项目是一个面向中小学的 **B 端 SaaS**(单校整体采购),把原"**班主任工作台**"(以下简称**原 HTML 项目**)的产品灵魂继承下来,扩展为一个**三角色协作平台**:

- **教师**:班主任、副班主任、任课老师。继承原 HTML 项目的全部核心功能(教室可视化、考勤、点评、随机点名、排座、成绩录入与分析、学生档案、AI 助手)。
- **管理**:校长、副校长、教导主任、年级组长、信息中心。看板、报表、组织架构管理、通知下发。
- **家长**:主家长、次要家长。只看自己孩子的信息,接收通知,结构化回执。

此外,平台提供**监控画面接入**模块,把学校本地已有摄像头的实时画面桥接到 Web 界面,按角色权限展示。

### 0.2 本文档的范围

本文档是**方向定稿**,覆盖:
- 系统架构与技术栈
- 三角色权限模型
- 数据模型
- 原 HTML → 新 React 项目的参考-重写策略
- 监控画面接入
- AI 层、部署、运维、合规

**不覆盖**:
- 具体 API 签名(等实现计划阶段细化)
- 具体 UI 稿(等交互设计阶段)
- 多租户 SaaS(**v2+ 再考虑**,v1 为单校定制化部署)
- 微信小程序 / 独立 App(**v2+ 再考虑**,v1 响应式 Web)
- AI 事件识别 / 行为识别(**明确砍掉**,v1 监控只做视频流接入)

### 0.3 与原 HTML 项目的关系

原 HTML 项目(`workstation-teacher/index.html`)**不再维护、不再发布、不并存运营**。本项目:

- **抛弃原项目代码**,新项目从零用 React + TypeScript 实现。
- **只借鉴原项目的产品设计**(功能、UI、交互、业务规则、AI 提示词),把原 HTML 作为**产品说明书 + UI 原型**来读。
- 原项目物理上保留在 `reference-html/` 目录,**不加入构建**。
### 0.4 命名约定

| 术语 | 含义 |
|---|---|
| **原 HTML 项目** | `workstation-teacher/index.html` 的单文件工作台 |
| **本平台 / 新项目** | 本文档描述的三角色 B 端 SaaS |
| **教师角色** | 班主任 + 副班主任 + 任课老师的统称 |
| **管理角色** | 校长 + 副校长 + 教导主任 + 年级组长 + 信息中心的统称 |
| **家长角色** | 主家长 + 次要家长的统称 |

## 1. 架构全景

### 1.1 系统边界

**在本平台范围内**:
- 唯一的 React Web 前端应用(内含三角色视图)
- Go 后端(单二进制)
- PostgreSQL / Redis / 对象存储
- 监控视频流接入层(ffmpeg + HLS)
- AI Gateway(代理第三方 LLM)

**明确不在范围内**:
- 摄像头硬件本身
- 原始视频流的处理与录制(由学校既有监控系统承担)
- 自建 AI 识别模型(接 LLM API,不自建)
- 微信小程序 / 独立 App(v1 不做)
- 多租户 SaaS(v1 不做)
- 跨校数据流转(v1 不做)

### 1.2 技术栈

| 层 | 选型 |
|---|---|
| 前端框架 | React 18 + TypeScript |
| 构建 | Vite |
| UI | Tailwind CSS + shadcn/ui |
| 状态 | TanStack Query(服务端) + Zustand(客户端) |
| 路由 | React Router v7 |
| 后端 | Go + Gin |
| ORM | sqlc(推荐) 或 GORM |
| 数据库 | PostgreSQL 16 |
| 缓存/会话 | Redis 7 |
| 对象存储 | MinIO(自建) 或 本地文件系统 |
| 认证 | JWT(access,短) + Refresh Token(长,存 Redis) |
| WebSocket | Gorilla WebSocket |
| 视频转码 | ffmpeg(拉流 RTSP → HLS) |
| 日志 | zerolog |
| 配置 | Viper + yaml |
### 1.3 通信方式

| 场景 | 协议 |
|---|---|
| 前端 → 后端(大部分) | REST + JSON |
| 前端 ← 后端(事件推送) | WebSocket(登录后按角色+班级订阅) |
| 后端 → 第三方 LLM | HTTPS REST,统一走后端 Gateway |
| 浏览器 → 视频流 | HLS over HTTPS,带签名 URL |

### 1.4 部署形态(v1 单校)

- 1 台服务器 / 工控机(2 核 4G 起),部署在**学校内网**
- Docker Compose 启动:`app`(Go 后端 + 静态前端 + ffmpeg) + `postgres` + `redis` + `caddy`(可选 HTTPS)
- 单一域名登录(例如 `banzhuren.<school>.edu.cn`),三角色共用入口
- 数据与视频流**均不出校园网**,备份由学校自行保管

## 2. 三角色权限模型

### 2.1 角色与身份(两层模型)

```
角色大类                   具体身份
──────────             ─────────────────────────────
教师                    班主任(1 个班的主要责任人)
                       副班主任(1 个班的辅助)
                       任课老师(多个班的某科)

管理                    校长 / 副校长(全校)
                       教导主任(全校教学业务)
                       年级组长(本年级)
                       信息中心(账号/配置,无业务数据)

家长                    主家长(1 个孩子的主要联系人,收通知)
                       次要家长(1 个孩子,只读)
```

一个用户可以**同时持有多种身份**(常见:语文老师教三班,同时是三班班主任;或者老师同时也是另一个班学生的家长)。登录后用户看到的是**身份语境**切换,而不是账号切换。

### 2.2 数据边界(作用域)

| 身份 | 可见数据范围 |
|---|---|
| 校长 / 副校长 / 教导主任 | 全校所有班级和学生 |
| 年级组长 | 本年级所有班级和学生 |
| 信息中心 | 全校组织架构 + 账号 + 系统配置,**无业务数据** |
| 班主任 | 自己班全部数据 |
| 副班主任 | 自己班的学生基本信息和日常事务,**不能导出敏感字段** |
| 任课老师 | 自己正在教的班级的部分字段 + 本科目成绩与点评 |
| 主家长 | 自己孩子的全部可见字段 + 班级公告 + 校级通知 |
| 次要家长 | 自己孩子的可见字段(只读) |
### 2.3 操作矩阵(节选,完整版见附录 B)

**学生档案字段级权限**:

| 字段 | 班主任 | 任课老师 | 年级组长 | 校长/主任 | 信息中心 | 主家长 | 次家长 |
|---|---|---|---|---|---|---|---|
| 基本信息 | 读写 | 读 | 读 | 读 | — | 读(自己孩子) | 读(自己孩子) |
| 家庭信息 | 读写 | — | 读 | 读 | — | 读写(自家) | 读 |
| 学习情况 | 读写 | 读写(本科目) | 读 | 读 | — | 读 | 读 |
| 性格特长 / 健康 | 读写 | 读 | 读 | 读 | — | 读 | 读 |
| **班主任个人笔记** | **仅本人读写** | — | — | — | — | — | — |

**成绩操作**:

| 操作 | 班主任 | 任课老师 | 年级组长 | 校长/主任 | 家长 |
|---|---|---|---|---|---|
| 录入 | 本班全科 | 本科目 | — | — | — |
| 查看 | 本班 | 本班本科目 | 本年级 | 全校 | 自己孩子 |
| 班级分析 | 本班 | 本班 | 本年级 | 全校 | — |
| 查看排名 | 本班 | 本班 | 本年级 | 全校 | **开关控制** |
| 导出 | 本班 | — | 本年级 | 全校 | — |

**监控视频访问**(§5 详述):

| 身份 | 范围 |
|---|---|
| 校长/主任 | 全校所有摄像头 |
| 班主任 | 自己班的摄像头 |
| 任课老师 | 正在上课的班的摄像头(按课表) |
| 家长 | **v1 不开放**(由产品决策明确砍掉) |

### 2.4 实现:RBAC + 轻 ABAC

- **角色(Role)**:预定义的字符串枚举:`principal`、`dean`、`grade_head`、`it_admin`、`homeroom_teacher`、`subject_teacher`、`assistant_teacher`、`primary_parent`、`secondary_parent`。
- **用户(User)**:单账号,可绑定多个 **RoleBinding**。
- **RoleBinding**:`{user_id, role_type, scope, academic_year_id, started_at, ended_at}`。`scope` 为 JSON,形如 `{class_id: ..., subject?: ...}`。
- **权限表(Permission)**:对象 × 操作 枚举,代码里定义。
- **决策流程**:每个请求携带 JWT → 加载用户所有 RoleBinding → 对每个被操作对象判断"作用域包含"+"权限授予"。
- **字段级权限** 不做完全的 RBAC,而是在**查询时按角色裁剪**(单 API 多视图)。
### 2.5 边界细节

- **老师同时是家长**:同账号多 RoleBinding,登录后可以切身份语境。
- **学年升级**:RoleBinding 带 `academic_year_id`,学年切换时旧绑定自动 `ended_at`,新绑定新建。
- **离职/毕业**:账号冻结(status=frozen),保留历史;毕业家长账号降级为"只读历史",或归档。
- **副班主任的字段级权限**:默认不能看家庭信息,防止副班主任私下联系家长;可写考勤和点评。

### 2.6 学校可配开关(管理端 → 学校设置)

| 开关 | 默认 | 影响 |
|---|---|---|
| 家长可见排名 | 关 | 关=仅段位(前 10%、前 30%);开=具体名次 |
| 家长收到负向点评 | 关 | 关=扣分不推家长 |
| 教师可见互相的点评频率 | 关 | 校长可见;老师不可互相监督 |
| 监控模块总开关 | 关 | 关=任何角色都看不到视频入口 |
| 家长可看监控(未来) | 关 | v1 保持关,v2 根据客户再决定 |
| AI 内容需审核后下发 | 开 | 开=AI 生成的"退步建议"需老师点"同意发送"再推家长 |

## 3. 数据模型

### 3.1 实体关系总览

```
School (学校,v1 单校 = 1 行)
  └─ AcademicYear (学年)
       ├─ Grade (年级)
       │    └─ Class (班级)
       │         ├─ Enrollment (学生-班级-学年)
       │         │    ├─ Attendance / Review / Score / Comment / GrowthRecord
       │         │    └─ (业务事件挂此)
       │         ├─ TeacherAssignment (老师-班级-身份-科目)
       │         ├─ SeatArrangement
       │         └─ Camera (0~N 个)
       └─ SchoolSetting (学校级配置)

User (账号)
  ├─ Teacher (老师档案)
  ├─ Parent (家长档案)
  └─ RoleBinding (权限实例,带学年)

Student (学生档案,无 user_id,v1 不登录)
  └─ ParentLink (多对多:学生 ↔ 家长)

跨对象:
  ├─ Notification (通知)
  ├─ Todo (私人待办)
  ├─ ClassDynamic (班级动态)
  ├─ Exam (考试,挂班级或年级)
  ├─ AITemplate / AIDraft
  └─ AuditLog
```

### 3.2 核心实体(关键字段,完整字段 schema 由实现计划细化)

**学校与学年**
- `School`: id, name, address, logo_url, timezone, locale, created_at, updated_at
- `AcademicYear`: id, school_id, name(如 "2026-2027"), start_date, end_date, is_active
- `Grade`: id, school_id, academic_year_id, name, order
- `Class`: id, school_id, academic_year_id, grade_id, name, seat_rows, seat_cols, homeroom_teacher_id(冗余)

**用户与档案**
- `User`: id, school_id, login_name, password_hash, display_name, avatar_url, phone, email, status, created_at, last_login_at
- `Teacher`: id, user_id, employee_no, title, subjects(text[]), bio
- `Student`: id, school_id, name, gender, student_no, birthdate, family_structure, learning_summary, personality, health_notes, tags(text[]), teacher_notes(jsonb,权限锁定)
- `Parent`: id, user_id, name, phone, wechat_openid(预留), occupation, relation_hint

**关联与权限**
- `Enrollment`: id, student_id, class_id, academic_year_id, seat_row, seat_col, entered_at, left_at, status(active/graduated/transferred)
- `TeacherAssignment`: id, teacher_id, class_id, academic_year_id, identity(homeroom/subject/assistant), subject, started_at, ended_at
- `ParentLink`: id, parent_id, student_id, relation, is_primary, notify_enabled
- `RoleBinding`: id, user_id, role_type, scope(jsonb), academic_year_id, started_at, ended_at

**业务事件(全部挂在 Enrollment)**
- `Attendance`: id, enrollment_id, date, status(present/leave/absent/late), reason, marked_by_user_id, marked_at
- `Review`: id, enrollment_id, reason_text, score_delta, category, subject, given_by_user_id, given_at, group_bonus
- `Exam`: id, class_id or grade_id, academic_year_id, name, type, date, subjects(jsonb)
- `Score`: id, exam_id, enrollment_id, subject, value, rank_in_class, rank_in_grade, entered_by_user_id, entered_at
- `Comment`: id, enrollment_id, academic_year_id, semester, content, generated_by_ai, reviewed_by_user_id, reviewed_at, delivered_to_parent, delivered_at
- `GrowthRecord`: id, enrollment_id, type, content, attachments(jsonb), created_by_user_id, created_at

**支撑**
- `Notification`: id, school_id, type, from_user_id, to_user_id, to_scope(jsonb), title, content, action_url, require_ack, ack_content, created_at, read_at, acked_at
- `Todo`: id, owner_user_id, content, done, due_at
- `ClassDynamic`: id, class_id, content, created_by_user_id, created_at
- `AuditLog`: id, user_id, action, object_type, object_id, ip, user_agent, success, extra(jsonb), at
- `SchoolSetting`: id, school_id, key, value(jsonb)
- `Camera`(§5): id, school_id, name, class_id(nullable), rtsp_url, rtsp_username(加密), rtsp_password(加密), location, enabled

### 3.3 学年升级

**核心规则**:所有带班级/身份/科目的东西挂 `academic_year_id`,升级 = 创建新学年 + 复制或改接关系,不删任何历史数据。

**升级流程**:
1. 管理员点"开始新学年" → 创建新 AcademicYear,`is_active` 从旧切新
2. 系统生成"升级建议表",管理员确认:哪届毕业、哪班升级、班主任如何分配、新生导入、转入转出
3. 执行:
   - 旧 Class `active=false`,新 Class 批量创建
   - 旧 Enrollment 加 `left_at`,新 Enrollment 创建(active)
   - 旧 TeacherAssignment `ended_at`,新建
   - 旧 RoleBinding `ended_at`,新建
   - 全部历史事件(考勤/成绩/点评/评语/成长)**完整保留不动**
4. 支持预览、回滚、留级(新班级 grade+1 但保持学号可配)
### 3.4 审计

- `AuditLog` 为 **insert-only**,记录所有敏感操作:
  - 读:看学生档案、导出成绩、下载附件
  - 写:录成绩、改档案、删点评
  - 管理:创建账号、修改权限、学年升级、修改监控配置
- 管理端有"查日志"界面,按用户/学生/时间/操作类型过滤

### 3.5 索引与性能

| 场景 | 关键索引 |
|---|---|
| 教师端打开教室 | `Enrollment(class_id, status)` + `Student(id)` |
| 今日概况 | `Attendance(enrollment_id, date)` 唯一索引 |
| 家长端打开首页 | `ParentLink(parent_id)` → `Enrollment(student_id, status=active)` |
| 全校考勤热力图 | `Attendance(class_id, date, status)` 复合索引(必要时物化视图/日汇总表) |

**性能参考值(v1)**:1 校 ≤ 100 班、≤ 5000 学生、≤ 500 老师、≤ 10000 家长;单台 2 核 4G 服务器量级即可承载。实际性能以真实环境压测为准。

## 4. 从原 HTML 到新 React 的"参考-重写"策略

原 HTML 项目**只作为参考资料存在**,新项目**从零用 React 重写**,**代码一行不复用**。原 HTML 当作"**产品说明书 + UI 原型**"来读。

### 4.2 考古阶段(编码前)

- 搭建新项目骨架(React + Vite + Go 骨架 + 空 schema)

  - UI 组件的隐式定义(教室、座位、模式切换、信息卡、档案抽屉)

  - AI 提示词模板(备课/评语/家长沟通话术各自的 prompt)
  - 教室小动画触发规则(hover 回头、举手、积分飘字)

## 5. 监控画面接入(最小版)

### 5.1 目标

**让后端把学校本地摄像头的实时画面桥接到 Web,按角色和班级权限展示。** v1 **不做** AI 识别、不做事件推送、不做通知规则、不做录像回放。

### 5.2 协议选型(RTSP → HLS)

- 摄像头原生推 **RTSP**,浏览器不能直接播。
- v1 采用 **RTSP → HLS**(ffmpeg 子进程转码),浏览器用 hls.js 播。延迟 5-15 秒,CPU 消耗低,运维简单。
- WebRTC(低延迟)作为 v2+ 升级路径,v1 不做。
- **云端中转永不做**(视频不出校承诺)。
### 5.3 架构

```
教室 IP 摄像头(多路) RTSP
          │ 校园内网
          ▼
   Go 后端(或独立 Worker)
     ├─ Camera 表(数据库中的接入配置)
     ├─ ffmpeg Worker Pool
     │    每路一个子进程,按需启动,30s 无访问自动停流
     ├─ 本地 HLS 片段缓存(内存或 /tmp,不持久化)
     └─ GET /api/v1/cameras/:id/stream.m3u8  (带签名)
          │
          ▼
   React 前端 <CameraPlayer>(hls.js)
   只在校园内网可访问
```

### 5.4 数据模型(Camera 表,§3 已声明)

```
Camera
  id, school_id,
  name            (如 "三年二班讲台方向"),
  class_id        (绑定班级,nullable=公共区域),
  rtsp_url        (学校内网地址),
  rtsp_username   (AES-256 加密存储),
  rtsp_password   (AES-256 加密存储),
  location        (教室/走廊/操场/食堂),
  enabled         (管理员可随时关),
  created_at
```

- 一个班级 **0~N 个** Camera
- Camera 可**不绑定**班级(公共区域,只有管理可见)

### 5.5 权限访问

每次请求 `/api/v1/cameras/:id/stream.m3u8`:

1. JWT 认证
2. 查该 Camera 的 class_id
3. 判定:
   - 管理角色 → 全校所有 Camera
   - 班主任 → class_id 是自己班 → 允许
   - 任课老师 → class_id 是自己正在上课的班(按课表)→ 允许
   - 家长 → **一律拒绝**(v1)
4. 签发**短期(60s)签名** URL 用于 .ts 片段请求

### 5.6 UI 融入教室图

**不做单独的"监控中心"页面**,把摄像头嵌入到教室可视化:

- 教师端:在教室图顶部/侧边放 `<CameraStrip>`(本班所有摄像头缩略),点开全屏;**日常模式默认隐藏**,点"看看教室"展开;直播画面有显眼"正在直播"水印。
- 管理端:全校看板侧放 `<CameraWallMini>`(一张学校班级图,每班对应一个缩略),点进去看单班或开 9 宫格;支持自动切换(每 10s 换一个班)。
- 家长端:**无入口**。

### 5.7 性能预算

- 一校 20-50 个教室,1-2 路/教室 → 20-100 路
- 同时在线观看正常 ≤ 5 路、高峰 ≤ 10 路
- 每路 ≈ 1 核 CPU(1080p) / 0.3 核(720p);单台 4 核 8G 服务器扛 10 路 720p 转码无压力
- 带宽**全部在校内局域网**,不占出口

### 5.8 配置和开关

管理端 → 学校设置 → 监控:

- **全局开关**:默认关,学校确认合规后开
- Camera 清单:增删改禁用、测试连接(ffmpeg 试拉 3s 回传预览图)
- 水印设置:学校名 + 时间等
- **"视频流不出校"自检**:系统启动检查外网是否能访问 RTSP 服务,报警
### 5.9 明确不做的东西(v1 边界)

| 功能 | 为什么不做 |
|---|---|
| AI 识别(人脸/行为/摔倒) | 用户明确砍掉 |
| 事件触发的自动通知 | 同上 |
| 录像回放 | v1 不做,等客户要求 |
| 云端存储视频 | 永不做("视频不出校"硬承诺) |
| 家长端查看 | v1 不做,等客户要求 |
| 跨校调看 | 多租户 v2+,v1 无需 |
| 对讲 / 喊话 | 不做 |

## 6. AI 层

### 6.1 原则继承

原 HTML 项目 AI 的三个设计原封保留:
- **多服务商可切换**(DeepSeek / 通义 / Kimi / 智谱 / 豆包 / 硅基流动 / 文心等)
- **"隐去姓名"默认开启**:学生名 → `【学生07】`,结果返回时在**后端**换回真名
- **AI 结果只是草稿**,老师审核后使用

### 6.2 Gateway 架构

```
前端 POST /api/v1/ai/generate
   { kind, context (studentIds, examIds...), extraPrompt }
          │
          ▼
AI Gateway (后端):
   1. 从数据库取真实数据(按老师权限过滤)
   2. 应用脱敏规则(姓名→编号,家长信息不进)
   3. 组装 Prompt(预置模板)
   4. 调用学校配置的 LLM 服务商
   5. 流式返回给前端
   6. 后处理:编号换回真名
   7. 可选:草稿存库(ai_drafts 表)
```

**关键**:
- 原 HTML 版"前端直连 LLM"的架构**不再使用**,所有调用走后端 Gateway。
- 原 HTML 版的 `ai-proxy.js` 本地转发**不再需要**,后端自身即转发点。
- 每个学校在管理端配置 LLM 服务商和 API Key,**所有老师共用**(学校付费)。老师端完全看不到 Key。

### 6.3 AI 场景(继承原版)

| 场景 | 触发 | 权限 |
|---|---|---|
| 备课 / 课件大纲 / 分层作业 | 老师 | 老师自己 |
| 班会方案 / 活动策划 / 工作总结 | 班主任 | 本班 |
| 家长群通知 / 沟通话术 | 班主任 | 本班(不含家长真实姓名/电话) |
| 家长会发言稿 | 班主任 | 本班考试数据(脱敏) |
| 期末评语(单条/批量) | 班主任 | 本班 |
| 成绩分析报告 | 老师 / 管理 | 对应权限范围 |
| 谈心谈话提纲 | 班主任 | 单生 |
| 生日祝福 | 老师 | 单生 |

v1 不新增 AI 功能,照原版做到位即可。
### 6.4 审计

所有 AI 调用在 `AuditLog` 里留一条:哪个老师、什么时间、什么场景、涉及哪些学生 ID、Token 消耗。管理端有 **"AI 使用情况"** 面板,校长可见老师 AI 用得多不多,同时用来算账(学校付的 API 费对应到人)。

## 7. 部署运维(v1 单校定制化)

### 7.1 部署清单

**硬件**:1 台 x86 服务器 / 工控机(2 核 4G 起),Linux(Ubuntu 22.04 LTS)或 Windows Server。磁盘 50-100 GB。

**安装介质**:一个 Docker Compose 项目目录:

```
workstation-deploy/
├── docker-compose.yml
├── .env.example
├── config/
│   ├── backend.yaml       # 后端配置(端口、JWT 密钥、主加密密钥)
│   └── school.yaml        # 学校定制项(名称、LOGO、学段、学年)
├── data/                  # 容器数据卷(PostgreSQL / Redis / 文件)

│   ├── install.sh         # 一键安装(问几个问题:学校名、超管密码、HTTPS 域名)
│   ├── backup.sh          # 全量备份(pg_dump + 数据卷 tar)
│   ├── restore.sh         # 恢复
│   └── upgrade.sh         # 升级
└── README.md
```

**docker-compose.yml 四个服务**:`postgres` / `redis` / `app` / `caddy`(可选 HTTPS)

**一键启动**:
```bash
./scripts/install.sh
docker compose up -d
```

### 7.2 升级

- 语义化版本号(`v1.0.0 → v1.1.0 → v2.0.0`)
- 升级 = `docker compose pull && docker compose up -d`,后端启动时自动跑数据库迁移
- 升级前**强制备份**(脚本提示)
- 向下兼容承诺:**1.x 内任意小版本可升可降**;大版本升级(1.x → 2.x)需显式迁移脚本

### 7.3 备份与恢复

- 全量备份 = `pg_dump` + 数据卷 `tar`
- 可每日自动,存本机 / 学校 NAS / 学校自己的云盘
- 恢复 = `./scripts/restore.sh <backup-file>`
- **备份永不离开学校**

### 7.4 远程运维

- 不做"后门"远程登录(违反合规承诺)
- 管理端有"**导出诊断信息**"按钮:导出一个**脱敏诊断包**(日志 + 配置 + 数据库 schema,不含业务数据)发给厂商

## 8. 合规与安全
### 8.1 账号安全

| 项 | 做法 |
|---|---|
| 密码存储 | bcrypt,成本参数 ≥ 10 |
| 密码策略 | 老师/管理 ≥ 8 位,包含两种字符;学校可配 |
| 登录限制 | 5 次错误锁定 15 分钟 |
| 会话 | JWT access token 15 分钟 + Refresh Token 7 天,Refresh 存 Redis 可撤销 |
| 2FA | 可选(学校管理端开关),基于 TOTP;v1 不强制 |

### 8.2 数据加密

- **传输**:全站 HTTPS(Caddy 自动签 Let's Encrypt;或学校自备证书)
- **静态**:业务数据库在学校服务器上,**磁盘加密由学校操作系统层负责**(建议 LUKS / BitLocker,但不强制)
- **敏感字段加密**:摄像头 RTSP 密码、第三方 LLM API Key,**AES-256 加密**存库,主密钥在 `backend.yaml`
- **主密钥管理**:安装时自动生成,学校自己保管;**备份时必须连同配置文件一起**

### 8.3 审计与日志

- `AuditLog`:敏感操作入库(§3.4)
- 系统日志用 zerolog(JSON),本地留 7-30 天(可配)
- **登录日志**单表,管理端可查
- **异常登录**(异地、凌晨)主动提醒当事用户和信息中心

### 8.4 隐私边界(写进产品承诺)

| 承诺 | 落地 |
|---|---|
| 学生数据不离开学校服务器 | 架构保证,SaaS 服务器不存业务数据 |
| 视频流不离开学校内网 | §5 架构保证,不走云端中转 |
| AI 调用脱敏处理 | 后端 Gateway 强制替换姓名 |
| 第三方 LLM 的选择与数据传出,是学校的选择 | 文档明示,合同条款约定 |

### 8.5 等保 / 合规(v1 阶段的最小集)

v1 **不追求完整的等保三级认证**(单校定制化不需要),但**做对的事情**,等 v2 规模化时不用推倒重做:
- 账号实名(老师工号、学生学号映射真实身份)
- 操作可追溯(AuditLog)
- 密码强制策略 + 可配定期更换
- 数据分级(普通 vs 敏感,代码里打标)
- 关键配置文件在学校自己手里

v2 冲等保,主要是**补文档和认证**,不是改架构。

### 10.1 v1 阶段的开放问题

### 10.2 v2+ 展望(本次范围外)

- **录像回放**(视频流依旧不出校,只做学校内查看)。

- **教育局 ToG 版本**(国标 28181、国产化、等保三级)。
- **跨校/跨区的数据汇总大屏**(匿名化聚合)。
- **AI 的更多场景**(自动化成绩分析、班级氛围预警、个性化成长建议)。
