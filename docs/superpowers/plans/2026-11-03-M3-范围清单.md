# M3 管理角色 · 范围清单

> M3 的目标:**校长能看全校**。本文件逐项写清 M3 做什么、不做什么、归 M3a 还是 M3b,以及用户 2026-11-03 拍板的取舍。
> 实施计划:[M3a 管理底座与看全校](2026-11-03-M3a-管理底座与看全校.md)、[M3b 联考报表、通知与学年](2026-11-03-M3b-联考报表通知与学年.md)。
> spec:[`2026-11-01-三角色协作平台-design.md`](../specs/2026-11-01-三角色协作平台-design.md) §2.2 / §2.4 / §2.6 / §3 / §4.4 / §6.4 / §8;D01–D17 一律不改。

## 为什么拆成 M3a / M3b

- M3 在路线图里有 12 块内容,外加 9 条遗留缺口,体量约为 M2d 的 3 倍,一份计划会失控。
- 按依赖切成两个能单独演示、单独打标的子里程碑:
  - **M3a 管理底座与看全校**:先有"谁是管理者、学校长什么样、账号从哪来",校长才能看全校。身份语境、管理端壳、权限点、组织架构、账号、标签池、学校设置、今日关注、全校看板,加上 M2c / M2d 的遗留缺口(学年类两条除外)。
  - **M3b 联考报表、通知与学年**:建立在 M3a 的组织与账号之上的"管学校"操作。年级联考与成绩汇总、月度考勤报告、审计查询、AI 使用面板与 AI 配置页、通知下发与 WebSocket、学年升级向导,以及学年类的两条遗留。
- M3b 计划写于 M3a 之前,**M3b 开工前由 M3b 协调会话对照 M3a 合并后的 main 复核一遍**(接口名、文件路径以代码为准,偏差写进 PR)。

| 子里程碑 | tag | 验收(可演示) |
|---|---|---|
| **M3a** | `v0.5.0-m3a-admin-org` | 校长(`principal01`)登录直接进管理端,"今日关注"看到全校今日出勤与关注名单,"全校看板"按年级看到每个班的教室缩略图,点进一个班看到只读教室和学生档案;信息中心(`itadmin01`)新建一个老师账号、把他设成某班任课老师,这位老师首次登录被要求改密码后能看到该班;信息中心冻结他,他下一次请求就被登出。E2E 全绿 + 浅 / 深 × 1920 / 1280 / 1024 / 768 / 375 走查 |
| **M3b** | `v0.5.1-m3b-reports-notify` | 校长下发一条全校通知,已登录的老师**不刷新**就在铃铛上看到并点开(已读),校长看到已读人数;教导主任建一场三年级联考,两个班的老师各自录分后,成绩汇总报表显示两班对比和年级名次;月度考勤报告能看、能导出 CSV、能打印;学年升级向导走完"预览 → 执行 → 回滚"。E2E 全绿 + 五种视口浅 / 深走查 |

## 用户拍板(2026-11-03)

1. **拆分**:拆两段 M3a / M3b(不拆三段)。tag `v0.5.0-m3a-admin-org`、`v0.5.1-m3b-reports-notify`,各自合并后由协调会话打,需用户批准。
2. **必选报表**:**两个都做**:月度考勤报告 + 考试成绩汇总。都在 M3b。
3. **成绩跨班对齐**:新增**年级联考**。教导主任 / 年级组长在管理端建一场年级考试,系统给该年级每个在读班建一场同名、同科目的班级考试,老师照常录分;成绩汇总只统计联考。spec §3.2"年级排名随年级联考在 M3 加"由此落地。
4. **账号安全**:2FA(TOTP)、异常登录提醒、密码定期更换**全部后移到 M5**。M3 只做账号增删改、重置密码、冻结即踢下线、本人改密码(见 C 节)。
5. **遗留缺口**:9 条**全部进 M3**(分配见 N 节)。
6. **通知**:M3 **只做下发 + 已读**。`require_ack` 字段先建好,结构化回执和发给家长归 M4。
7. **年级组长与学年升级**:不做学校开关;学年升级向导的"人员"一步**逐个指定**每个新年级的组长,默认跟届(即现状),管理员可改成留在原年级或换人。

## 计划自定项(请审阅时留意)

1. **身份语境的判定**:`GET /me/contexts` 返回 `teacher` / `admin`(M4 加 `parent`)。有教师绑定 → 有 `teacher`;有 `principal / dean / grade_head / it_admin` 任一绑定 → 有 `admin`。两个都有时默认进上次的语境,第一次进教师端。
2. **任职一处写三张表**:管理端改任职时同时写 `teacher_assignments`、`role_bindings`、`classes.homeroom_teacher_id`(冗余列),三者在一个事务里,保证学年升级、教师端"我的班级"读到一致的结果。
3. **学段、第二学期挂在哪**:学段挂年级(`grades.stage`),第二学期开学日期挂学年(`academic_years.term2_start`)。原版这两项是"班级信息"里的字段;我们是全校一套,放在组织架构里改,班级信息页只读展示。
4. **首次登录改密码**:新账号和被重置的账号带 `must_change_password`,登录后只能先改密码。这是账号管理的基本要求,不是"密码定期更换"(那个后移 M5)。
5. **冻结即时生效**:每次请求都会检查账号状态(M1 已有),冻结后下一次请求就 401;刷新令牌同时全部作废。重置密码只作废刷新令牌,手上的访问令牌最多还能用 15 分钟(spec §8.1 的访问令牌时长),不额外加令牌版本号。
6. **通知分两张表**:`notices`(一次发送一行:标题、正文、对象、发送人、撤回时间、`require_ack`)+ `notice_recipients`(每个收件人一行:已读时间、回执时间)。spec §3.2 的 `Notification` 字段语义不变,只是按"一次发送 / 每个收件人"拆开,计划里同步改 spec §3.2 的这一行。
7. **WebSocket 走 Redis 发布订阅**:后端多进程时也能推到;连接 `GET /api/v1/ws`,连上后 5 秒内要发 `{"type":"auth","token":...}`,否则关闭。账号冻结时推 `session.revoked` 并断开。
8. **年级联考的班级考试由系统维护**:老师端能录分、能看,不能改名、改科目、删除(409 `EXAM_MANAGED_BY_GRADE`)。
9. **学年升级向导的权限**:只给校长和教导主任;信息中心没有业务数据,不能做升级(升级要看学生名单)。
10. **全校看板不做懒加载**:按年级分页签,一个页签里最多十几个班,直接渲染缩略图;spec §3.5 的上限(100 班)下单页签不会超过 20 张。
11. **学生档案抽屉跨角色复用**:管理端直接用教师端的档案抽屉组件,字段已由后端按身份裁剪;管理端隐藏"我的笔记"和所有写入口。
12. **种子账号**:`principal01`(校长)、`dean01`(教导主任)、`gradehead03`(三年级组长)、`itadmin01`(信息中心),密码 `dev123`,姓名虚构。
13. **往年班级只读页(M3b 复核追加,台账 L1)**:管理端"往年班级"按学年列出往年的班,点进去只读看名单与成绩;可见范围与看全校相同,只认领导绑定——校长、教导主任看全部往年班,年级组长的绑定挂在当前学年的年级上,看不到往年班。教师端按学年回看不做(M5 前按反馈定)。
14. **同班只有一位在任班主任(M3b 复核追加,台账 L6)**:`teacher_assignments` 加部分唯一索引,任命与删班先锁班级行。
