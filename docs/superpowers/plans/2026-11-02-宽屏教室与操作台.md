> **开始前先读 [`../../../AGENTS.md`](../../../AGENTS.md)、[设计稿](../specs/2026-11-02-宽屏教室与操作台-design.md) 和 [M2a.5 计划](2026-11-01-M2a5-UI基础与打磨.md) 的 Global Constraints。** 本计划建立在 `v0.2.5-m2a5-ui`(main @ f5c3269)**实际合并的代码**之上;计划中的行号、类名与执行时代码不一致的,以代码为准做最小修正,并写进 PR 的"偏差"小节。

**Goal:** 把教室场景画宽到约 16:9(中央安全区 + 两侧装饰)、让画布在"适应"时锁定且放大后拖不出边界,并把教室页的模式切换与操作合成一条底部操作台、顶栏收成"班级信息 + 主题 + 头像菜单"。**只改 UI,不改行为和接口。**

**Architecture:** `computeLayout` 新增 `aspect` 选项:今天的整间教室原样作为安全区平移到中央,两侧补出对称的两翼区域,`fitView` 只按安全区宽度算比例,所以核心大小与今天逐像素相同、窄屏只裁两翼。视口改成"适应(锁定)/ 放大(可拖、夹在场景内)"两种状态,缩放钮作为舞台内悬浮层由 `ClassroomMap` 自己渲染。新增自写的非 portal `Popover` / `Menu`,供排座行列弹层、"⋯"更多、头像菜单使用。

**Tech Stack:** 沿用 M2a.5(React 18.3 / Vite 5.4 / Tailwind 3.4 / shadcn 2.3.0 生成组件 / lucide-react / Vitest + Testing Library / Playwright);**不新增任何依赖**。

**Spec:** [设计稿 `2026-11-02-宽屏教室与操作台-design.md`](../specs/2026-11-02-宽屏教室与操作台-design.md)(本计划的直接依据);总 spec [`2026-11-01-三角色协作平台-design.md`](../specs/2026-11-01-三角色协作平台-design.md) §4.4、§4.6、附录 A(Task 1 新增 D14)

## Review Focus

以下五条是设计稿没逐字写成测试、但最可能咬到真实老师的输入 / 失败模式,测试已落在对应 task:

1. **一体机上手掌一蹭,画面跑掉**:老师站在大屏前,手臂扫过舞台或触控板双指一滑 → "适应"时拖动和普通滚轮都无效;放大后拖到尽头,场景仍盖满舞台、露不出底色;点"适应"一键回位。落点:Task 2 `does not pan at fit, by drag or by plain wheel`、`pans after zooming in but never drags the scene off the stage`、`clampView keeps a zoomed axis covering the stage and centres a short one`。
2. **平板 / 1024 投影上核心被裁或变小**:画宽后若按整幅场景适应,黑板和名牌会缩小;若裁切按场景左边对齐,会裁掉第一列座位 → 适应比例只按安全区宽度算、场景居中。落点:Task 1 `fits by the safe width so the core keeps its size and only the wings are cropped`;Task 10 `core stays whole at {宽}×{高}`(四种视口)。
3. **排座行列弹层里输入了数字,点别处就丢了**:老师在"排数"里打 `8`,直接点舞台去看效果,弹层关了、数字没生效(或反过来,按 Esc 想取消却生效了)→ 点外面先失焦提交再关闭;Esc 放弃未提交输入。落点:Task 7 `typing a row count then leaving the popover applies it`、`Escape closes the size popover without applying typed text`;Task 10 `seat size popover applies a typed value when clicking the stage`(真浏览器事件顺序)。
4. **投屏全屏时"⋯"菜单 / 行列弹层看不见**:若浮层 portal 到 `body`,全屏时只有教室页根节点的子树可见,菜单打开了却看不到、还抢走焦点 → `Popover` / `Menu` 不走 portal,渲染在触发按钮旁边。落点:Task 3 `renders inside its own subtree, never in a portal`;Task 7 `more menu opens inside the fullscreen root while presenting`。
5. **缩到底时键盘焦点掉到页面顶部**:用外接键盘的老师连按"缩小",到适应比例时按钮若变 `disabled`,焦点丢失 → 到上下限用 `aria-disabled`,点击无效果、焦点留在按钮上。落点:Task 2 `zoom controls stay focusable at their limits and do nothing there`。

**Interfaces:**
- Produces:

  - `viewport.ts`:`fitView(content: Size, stage: Size, safeW = content.w): View`(公式见设计稿 §5.3)。
  - `useViewport(stageRef, content: Size & { safeW?: number }, enabled = true)`:适应时用 `content.safeW ?? content.w`。
  - `art/Wings.tsx`:`export default memo(function Wings({ layout }: { layout: Layout }))`——`layout.wings` 为空时返回 `null`;否则输出 `<g className="cr-wings" aria-hidden="true">`,内含 `<g data-wing="left">` 与 `<g data-wing="right">`,各自先画 `wall` 矩形(`fill={ROOM.wall}`)和底部 26 px 踢脚线(`fill={ROOM.trim}` + `stroke={ROOM.desk}` 宽 3 的顶线,与 `FrontWall` 相同),并用 `useId()` 生成的 `<clipPath>`(一个 wall、一个 floor 矩形)裁住各自区域。Task 4/5 在这两个 `<g>` 里加装饰。
  - `ClassroomMap` 非 `mini` 时 `computeLayout(rows, cols, { decor: true, frontWall: true, aspect: SCENE_ASPECT })`;`Scene` 在 `<Room>` 之后、`<Zones>` 之前画 `<Wings layout={L} />`;`useViewport` 收到 `{ w: L.width, h: L.height, safeW: L.safe.w }`。
