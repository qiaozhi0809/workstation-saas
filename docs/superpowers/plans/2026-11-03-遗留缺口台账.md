## 用途与维护规则

本文件是**所有里程碑报过的缺口的唯一台账**。以前缺口只散落在 PR 描述的"已知缺口"和会话笔记里,段会话归档后没人汇总,审计时 19 条漏网。

维护规则:

1. 段会话 PR 的"已知缺口"、协调会话收尾总结里的遗留问题,都要登进本台账,并写明**归属**(里程碑 / task)。没有归属的缺口不算登记完。
2. 写任何新计划之前,先对**整份台账**对账(不只看上一个里程碑),把归属本里程碑的条目并进计划的 task。
3. 每个里程碑收尾时更新台账:把状态改为"已修复"并附证据(PR / 提交),或改为"放弃"并写理由。
4. 编号 L1–L19 取自审计;新增条目从 L20 起顺延,编号不复用。
5. 状态取值:待办 / 已转 M3a / 已排计划(写作"已排 M3b Task N")/ 已修复(含"代码侧已修复")/ 放弃 / v1 之后(写明等什么:客户反馈或依赖的功能)。
