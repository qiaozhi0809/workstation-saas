# M5 监控、部署与 v1 发布 · 范围清单

> M5 的目标:**具备交付第一个客户的条件**。也就是在一台干净的 Ubuntu 上用 `install.sh` 一键装起全套;学校能备份、恢复、升级;账号安全达到 spec §8 的要求;老师能在教室图里看本班摄像头;遗留缺口清完。本文件写清 M5 做什么、不做什么、归哪个子里程碑,以及用户 2026-11-05 拍板的取舍。
> 实施计划:[M5a 部署与运维](2026-11-05-M5a-部署与运维.md)、[M5b 账号安全](2026-11-05-M5b-账号安全.md)、[M5c 监控与课表](2026-11-05-M5c-监控与课表.md)、[M5d 学校设置、引导与打磨](2026-11-05-M5d-学校设置引导与打磨.md)。
> spec:[`2026-11-01-三角色协作平台-design.md`](../specs/2026-11-01-三角色协作平台-design.md) §5 / §7 / §8;原版参考 `reference-html/features-extracted.md` §11.1(欢迎页)、§10.7 / §15.8(本地备份,改由 `backup` / `restore` 脚本承担)。**D01–D17 一律不改**;D13 由本次拍板落定结论(见第 3 条),不改决策本身。

## 为什么拆成四段、为什么这个顺序

| 子里程碑 | tag | 迁移 | 一句话 | 验收(可演示) |
|---|---|---|---|---|
| **M5a 部署与运维** | `v0.7.0-m5a-deploy` | 无 | 生产镜像、Docker Compose 包、四个脚本、迁移预检、定时任务、诊断包 | 在干净的 Ubuntu 24.04 虚拟机上解开离线包,`./scripts/install.sh` 回答学校名、管理员密码、访问地址,几分钟后浏览器用 HTTPS 打开登录页,用初始管理员登录、被要求改密码;`backup.sh` 生成备份,删库后 `restore.sh` 恢复,数据一致;管理端"导出诊断信息"下载到脱敏的 zip。CI 新增 `deploy` 任务跑通同样的流程 |
| **M5b 账号安全** | `v0.7.1-m5b-security` | `0011` | 两步验证(TOTP,可选)、登录日志、异常登录提醒、密码定期更换、改 / 重置密码即踢下线 | 学校打开"允许两步验证",老师在账号设置里扫码开启,下次登录要输验证码;信息中心在"登录日志"里看到这次登录;凌晨或从没见过的网段登录时,本人和信息中心收到"账号安全提醒";学校设"90 天改一次密码"后,过期账号登录要先改密码;管理员重置某老师密码时,该老师已打开的页面不刷新就回到登录页。**首次用 `upgrade.sh` 把 M5a 装好的机器升到 M5b(真正跑迁移 0011)** |
| **M5c 监控与课表** | `v0.7.2-m5c-cameras` | `0012` | 课表实体、摄像头管理、RTSP→HLS 转流、`CameraStrip` / `CameraWallMini` | 学校打开"监控"开关,信息中心录入一路摄像头(CI 用假摄像头),测试连接看到预览图;班主任在教室页点"看看教室"看到本班直播,画面有"正在直播"水印;任课老师只在课表上自己这节课的时间段内看得到;校长在全校看板旁看到每班的摄像头,点开单班或九宫格,可以每 10 秒自动换班;家长端没有任何入口 |
| **M5d 学校设置、引导与打磨** | `v1.0.0-rc.1`(发布候选);用户验收后打 `v1.0.0` | `0013` | 学校级科目目录与及格线(L2 / L37)、欢迎页与首次使用引导、打磨清单 | 校长把及格线改成 70%,老师端分析、AI 统计、成绩汇总三处同时变;联考只能从科目目录里选科目;新老师首次登录看到欢迎页并选形象;管理员首次进管理端看到"开学准备"清单;台账归 M5 的条目全部关闭或写明去向;在干净的 Ubuntu 上从 `v0.7.2` 离线包升级到 `v1.0.0-rc.1`,全量 E2E + 走查通过 |

- **部署包先落地**:M5b / M5c / M5d 各带一条迁移,每个子里程碑收尾时都用 `upgrade.sh` 把上一个 tag 的离线包实际升级一遍,升级路径在交付前就被反复验证。
- **安全在监控之前**:摄像头的 RTSP 密码要用加密存储,M5b 先把 AES-GCM 附加数据(台账 L95)改好,M5c 直接用新格式。
- **四段串行**,一次只开一个里程碑协调会话;M5b / M5c / M5d 的计划写于 M5a 开工之前,**各自开工前由协调会话对照上一段合并后的 main 复核一遍**(迁移号、函数名、文件路径以代码为准,偏差写进第一个 PR 并在计划文首加"复核记录")。

## 用户拍板(2026-11-05)

1. **流媒体组件**:**自研 ffmpeg 工作进程**,按 spec §5.3:单独一个 `stream-worker` 容器管理 ffmpeg 子进程,按需拉流,30 秒没人看就停;HLS 片段由后端带 60 秒签名下发,前端用 hls.js 播放。判权和签名都在自己的代码里。开发与 CI 用 ffmpeg 生成的测试画面当假摄像头(只在开发 / CI 的 compose 里,不进交付包)。
2. **部署目标与介质**:**只支持 Ubuntu 22.04 / 24.04 LTS x86_64**,目标机已装 Docker Engine 与 compose 插件。发版时用 `docker save` 把镜像打成一个 tar,和 `workstation-deploy/` 目录一起交付,`install.sh` 用 `docker load` 导入,学校内网不需要访问镜像仓库,镜像也不公开。HTTPS 可以用学校自备证书,也可以用 Caddy 内部签发的证书。spec §7.1 里的 Windows Server 在 v1 不支持(M5a Task 9 同步改 spec §7.1 原文)。
3. **D13 源码保护**:**只评估 + 一次 Nuitka 试编译**(M5a Task 8),写评估报告(能否编译、启动与性能差别、构建耗时、坑);v1 交付镜像**不编译**,构建脚本留开关 `WS_BUILD_NUITKA=1`(默认关)。D13 的结论记为"已评估,v1 不启用"(决策本身"推迟到 M5 部署阶段解决"不改)。
4. **拆分与顺序**:**四段串行**:M5a 部署 → M5b 安全 → M5c 监控 → M5d 打磨 = 发布候选 `v1.0.0-rc.1`;用户在干净的 Ubuntu 上验收后打 `v1.0.0`。

此前已定、本次沿用:2FA / 异常登录提醒 / 密码定期更换在 M5(2026-11-03);课表随监控一起定(2026-11-02);欢迎页 / 首次使用引导在 M5(2026-11-02);L2 学校级科目与及格线在 M5(2026-11-04);L21 成长记录附件 v1 不做(2026-11-04)。

## 计划自定项(请审阅时留意)

1. **配置用 `.env`,不用 YAML**:spec §7.1 画的是 `config/backend.yaml` + `school.yaml`;后端现在就是读 `WS_*` 环境变量(pydantic-settings),改 YAML 没有收益。改为 `workstation-deploy/.env`(`install.sh` 生成,权限 600)。学校名等存在数据库里(M3a 已有学校设置)。M5a Task 9 同步改 spec §7.1 的目录图。
2. **多出两个服务**:`scheduler`(定时任务,与 `app` 同一个镜像,命令不同)、`stream-worker`(M5c,`workstation-stream` 镜像 = 后端代码 + ffmpeg)。`app` 不装 ffmpeg。
3. **网页由 Caddy 直接发**:前端构建产物打进 `workstation-web` 镜像(Caddy),`/api/*` 反向代理到 `app:8080`(含 WebSocket);同源部署,不需要 CORS。
4. **"1.x 可升可降"的落地**:只写升级方向的迁移;降级 = 用 `upgrade.sh` 升级前自动做的那份备份 + 旧版本离线包执行 `restore.sh`。`deploy/README.md` 写明。
5. **迁移预检的规则**:以后每条会加 CHECK / 唯一约束 / NOT NULL 的迁移,都必须在 `app/deploy/precheck.py` 登记一条预检(AGENTS.md 增加这条约束);预检只读、不修数据,报告里给出定位用的 SQL。
6. **初始管理员**:`install.sh` 调 `python -m app.cli init-school` 建学校行(`id = WS_SCHOOL_ID`)与一个 `it_admin`(信息中心)账号,`must_change_password = true`;建首个进行中的学年(按日期推算,如 `2026-2027学年`;G-1,PR #89,段 G 验收发现原写法"不建学年"会让管理员建不了年级和班级),不建年级、班级,由管理员在管理端建("开学准备"清单引导)。已初始化时再跑直接退出,不改数据。
7. **两步验证不做恢复码**:丢了手机找信息中心"重置两步验证"(要求 `account.manage`,本人下次登录可以重新开启;审计 `account.totp_reset`)。单校场景里信息中心就在学校,恢复码反而容易被抄走。
8. **异常登录不做归属地**:学校服务器多半不联网,也没有 IP 库。"异地"按"90 天内这个账号没用过的网段"判断;新账号前 3 次成功登录不判。提醒以**系统通知**发出(`notices.from_user_id = NULL`,收件人是本人和全部在用的信息中心账号),不发短信 / 邮件。
9. **密码有效期从迁移那天起算**:迁移 0011 给 `users` 加 `password_changed_at`,已有账号回填为迁移时刻,避免一开启就全员过期。
10. **作息时间全校一套**:不同年级作息不同的学校,v1 按最长的一套配,任课老师可看时段以课表的节次为准;按年级分作息留给 v2。
11. **任课老师的可看时段**:课表上"这个老师、这个班、今天星期几、这一节",从开始前 5 分钟到结束;寒暑假、调课不处理(课表是"每周固定");换课后由管理员改课表。
12. **"视频流不出校"自检的落地**:后端没法从校内探测"外网能不能访问 RTSP"。改为三道:① 摄像头地址必须解析到内网地址;② 播放接口只接受内网来源(经 `WS_TRUSTED_PROXIES` 取真实 IP);③ `stream-worker` 启动时检查所有摄像头地址,发现公网地址就在管理端摄像头页顶部告警并拒绝拉流。
13. **水印不可配**:固定为"正在直播 · 校名 · 当前时间 · 观看人姓名",叠在播放器上(前端渲染,不烧进视频),不提供设置。
14. **及格线按比例,不按分数**:学校设"及格 = 满分 × 比例",各科满分不同也适用;不做"每科单独设及格分"。
15. **欢迎页只问形象**:原版还问称呼和任教学科;我们的称呼由账号决定、科目由任职决定,欢迎页只确认显示名、选形象(写进已有的 `user_preferences.teacher_figure`),再加一句"你的班级已由学校配置好"。
16. **v1.0.0 的打法**:M5d 段 G 打 `v1.0.0-rc.1`;用户在干净的 Ubuntu 上按 `deploy/README.md` 自己装一遍并在真实教室投屏验收后,协调会话在同一提交上打 `v1.0.0`(需用户明确说"打 v1.0.0")。
